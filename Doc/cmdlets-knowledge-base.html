Knowledge Base Cmdlets

These cmdlets interact with the Juriba Knowledge Base -- a curated database of known applications, their versions, download sources, and proven install/uninstall command lines. The Knowledge Base enables automated application discovery and command detection without manual research.

Search-JuribaAppRKnowledgeBase

Searches the Juriba Knowledge Base for applications by name or retrieves version and source details for a specific application. Supports two API backends: the instance-proxied endpoint (v5.2) and the UDA direct API (v6.0+).

Syntax

# Parameter Set: Search (by name)
Search-JuribaAppRKnowledgeBase
    -Search <String>
    [-Instance <String>]
    [-APIKey <String>]
    [-UseUDA]
    [-UDAKey <String>]
    [-UDAHost <String>]
    [-Limit <Int32>]

# Parameter Set: ById (versions and sources)
Search-JuribaAppRKnowledgeBase
    -ApplicationId <String>
    [-Instance <String>]
    [-APIKey <String>]
    [-UseUDA]
    [-UDAKey <String>]
    [-UDAHost <String>]
    [-Limit <Int32>]

Parameters

ParameterTypeStatusDescription
-SearchStringRequired*Search term to query the Knowledge Base by application name. Part of the Search parameter set.
-ApplicationIdStringRequired*KB application GUID to retrieve version and source details. Part of the ById parameter set.
-InstanceStringOptionalInstance URL. Not required if connected via Connect-JuribaAppR.
-APIKeyStringOptionalAPI key. Not required if connected via Connect-JuribaAppR.
-UseUDASwitchOptionalCall the UDA API directly (uda.api.juriba.app) instead of the instance-proxied endpoint. Required for v6.0+ until the instance proxy is fixed.
-UDAKeyStringOptionalSeparate API key for the UDA service. If not specified, the AppR connection API key is used.
-UDAHostStringOptionalOverride the UDA API host. Default: https://uda.api.juriba.app.
-LimitInt32OptionalMaximum number of results to return (UDA v2 endpoint only). Default: 25.

* One of -Search or -ApplicationId is required. They belong to different parameter sets and cannot be used together.

API Backends and Auto-Fallback

The cmdlet supports two API backends:

  • Instance-proxied (default): Calls your App Readiness instance's api/kb/ endpoints. This is the simplest path and works with v5.2 instances.
  • UDA direct: Calls the Juriba UDA API at uda.api.juriba.app. Use -UseUDA to select this path explicitly.

When the instance-proxied endpoint is used (the default), the cmdlet automatically falls back to the UDA API if the proxied call fails. This handles cases where the instance proxy returns errors (such as the v6.0 RC proxy issue that returns HTTP 500).

v6.0 Instance Proxy Issue: As of the v6.0 release candidate, the instance-proxied KB endpoint returns HTTP 500 for API key authentication. The cmdlet handles this transparently via auto-fallback, but you can avoid the failed request by specifying -UseUDA directly.

When to Use

  • Use -Search to find applications by name before uploading an installer. The KB may already have the application catalogued with known-good install commands.
  • Use -ApplicationId to drill into a specific application's versions and download sources. This is the second step after searching by name.
  • Use -UseUDA when connecting to a v6.0+ instance, or when the instance proxy is known to be unreliable.

Example 3: Complete flow -- search, pick an app, get the download URL

# Step 1: Search for the application
$results = Search-JuribaAppRKnowledgeBase -Search "7-Zip" -UseUDA
$app = $results | Where-Object { $_.name -eq "7-Zip" } | Select-Object -First 1
Write-Host "Found: $($app.name) ($($app.id))"

# Step 2: Get version details
$versions = Search-JuribaAppRKnowledgeBase -ApplicationId $app.id -UseUDA
$latest = $versions | Sort-Object version -Descending | Select-Object -First 1
Write-Host "Latest version: $($latest.version)"
Write-Host "Download URL: $($latest.downloadUrl)"

# Step 3: Download and upload to App Readiness
$installerPath = "C:\Temp\$($latest.version)\7-Zip-Setup.exe"
Invoke-WebRequest -Uri $latest.downloadUrl -OutFile $installerPath
$upload = Send-JuribaAppRSetupFile -FilePath $installerPath

Get-JuribaAppRCommandSuggestion

Queries the App Readiness command suggestion engine for an uploaded setup file. The engine uses hash matching against the Juriba Knowledge Base, rules-based programmatic detection, and AI-based analysis to suggest the best install and uninstall command lines.

This cmdlet is called automatically by New-JuribaAppRApplication when -CommandLine and -SkipCommandSuggestion are not specified. You can also call it directly to inspect the full set of candidates before creating an application.

Syntax

Get-JuribaAppRCommandSuggestion
    -UploadId <String>
    -FileName <String>
    [-Instance <String>]
    [-APIKey <String>]
    [-Name <String>]
    [-Manufacturer <String>]
    [-Version <String>]

Parameters

ParameterTypeStatusDescription
-UploadIdStringRequiredUUID of the uploaded file (from Send-JuribaAppRSetupFile).
-FileNameStringRequiredFile name of the uploaded setup file.
-InstanceStringOptionalInstance URL override.
-APIKeyStringOptionalAPI key override.
-NameStringOptionalApplication name. Improves KB matching accuracy.
-ManufacturerStringOptionalManufacturer name. Improves KB matching accuracy.
-VersionStringOptionalApplication version. Improves KB matching accuracy.

Suggestion Sources

The command suggestion engine returns candidates from three sources, each identified by a numeric source value:

SourceValueDescriptionPriority
Juriba Knowledge Base3Commands verified across the Juriba customer base. Matched by file hash or application identity.Highest
Programmatic1Rules-based detection from file naming conventions, installer type (MSI, NSIS, Inno Setup, etc.), and embedded metadata.Medium
AI2Machine-learning suggestions based on file analysis. Used as a fallback when KB and programmatic sources have no match.Lowest

Selection Logic

When New-JuribaAppRApplication processes the suggestion response, it selects a single install command using this logic:

  1. Filter commands to type = 1 (install commands only; uninstall is handled by the product).
  2. Iterate sources in priority order: KB (3), Programmatic (1), AI (2).
  3. Within each source, prefer commands where lastResult > 0 (previously successful), then rank by successRate descending.
  4. Select the top candidate from the first source that has any matches.

When to Use

  • Call this directly when you want to inspect all suggestion candidates before committing to a command line.
  • Useful for debugging when New-JuribaAppRApplication selects an unexpected command -- you can see the full ranked list.
  • In most automation workflows, you do not need to call this directly; New-JuribaAppRApplication handles it internally.

Examples

Example 1: Get suggestions for an uploaded file

$upload = Send-JuribaAppRSetupFile -FilePath "C:\Installers\7z2407-x64.exe"
$cmds = Get-JuribaAppRCommandSuggestion -UploadId $upload.Uuid -FileName $upload.FileName `
    -Name "7-Zip" -Manufacturer "Igor Pavlov" -Version "24.07"
$cmds

$cmds = Get-JuribaAppRCommandSuggestion -UploadId $upload.Uuid -FileName $upload.FileName
$installCmds = $cmds.commands | Where-Object { $_.type -eq 1 }
$installCmds | Sort-Object source | Format-Table source, command, successRate, lastResult -AutoSize
Sample Output

------ -------                                   ----------- ----------
     1 7z2407-x64.exe /S /D="C:\Program Files..."       85.0          0
     2 7z2407-x64.exe /S /SILENT                         60.0          0

Example 3: Use suggestions to manually set the command line

# Get suggestions
$cmds = Get-JuribaAppRCommandSuggestion -UploadId $upload.Uuid -FileName $upload.FileName `
    -Name "Custom App" -Manufacturer "Contoso" -Version "2.0"

# Pick the best KB suggestion if available
$kbCmd = $cmds.commands | Where-Object { $_.type -eq 1 -and $_.source -eq 3 } |
    Sort-Object successRate -Descending | Select-Object -First 1

if ($kbCmd) {
    Write-Host "Using KB command: $($kbCmd.command) (success rate: $($kbCmd.successRate)%)"
    $app = New-JuribaAppRApplication -Uuid $upload.Uuid -FileName $upload.FileName `
        -FileSize $upload.FileSize -TotalChunks $upload.TotalChunks `
        -CommandLine $kbCmd.command -SkipCommandSuggestion -RunImmediately
} else {
    Write-Host "No KB match found, letting the engine auto-select."
    $app = New-JuribaAppRApplication -Uuid $upload.Uuid -FileName $upload.FileName `
        -FileSize $upload.FileSize -TotalChunks $upload.TotalChunks -RunImmediately
}
Sample Output 
Using KB command: CustomApp-Setup.exe /quiet /norestart (success rate: 92.3%)

Uuid     : e8b2d4a1-3c6f-4e9a-b71d-2a5f8c0e9d34
FileName : CustomApp-Setup.exe
Status   : Submitted
Note: The commands array contains both install (type = 1) and uninstall (type = 2) suggestions. The New-JuribaAppRApplication cmdlet only uses install commands; uninstall is intentionally left empty because the product detects the correct uninstall command during the packaging phase.
Note: The API request body uses the field name applicationManufacture (without the trailing "r"). This is a known API quirk. The cmdlet handles this mapping internally -- always pass -Manufacturer with the standard spelling.
