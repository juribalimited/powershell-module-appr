Publishing Cmdlets

Publishing is the final step in the application readiness pipeline: once an application has been packaged, tested, and passed quality review, it is published to one or more deployment targets. App Readiness supports publishing to Microsoft Intune, Microsoft Endpoint Configuration Manager (MECM/SCCM), and custom Generic Integration endpoints. These cmdlets let you discover available connectors, inspect publishing templates, and trigger publish operations from PowerShell.

Get-JuribaAppRIntegrationConnector

Synopsis

Gets integration connectors configured in Juriba App Readiness.

Description

Integration connectors represent the external deployment targets that App Readiness can publish packages to. Each connector defines a connection to a specific system -- for example, a Microsoft Intune tenant, an MECM site server, or a custom generic integration endpoint. Connectors store the credentials, endpoint URLs, and configuration needed to push packages to that target. Use this cmdlet to list all configured connectors or retrieve details for a specific one by ID.

Syntax

# List all connectors
Get-JuribaAppRIntegrationConnector

# Get a specific connector by ID
Get-JuribaAppRIntegrationConnector -ConnectorId <Int32>

Parameters

ParameterTypeStatusDescription
-Instance String Optional The URL of the App Readiness instance. Not required if connected via Connect-JuribaAppR.
-APIKey String Optional The API key for authentication. Not required if connected via Connect-JuribaAppR.
-ConnectorId Int32 Optional The unique identifier of a specific connector to retrieve. When omitted, all connectors are returned.

When to Use

Use this cmdlet at the start of a publishing workflow to discover which integration targets are available. The returned connector IDs and types are needed as inputs when calling Invoke-JuribaAppRPublishIntune, Invoke-JuribaAppRPublishMECM, or Invoke-JuribaAppRPublishGeneric. It is also useful for inventory audits and configuration validation scripts that need to confirm the correct connectors are in place.

Examples

Example 1 -- List all integration connectors

Get-JuribaAppRIntegrationConnector
Sample output 
id          : 1
name        : Intune Production
type        : Intune
enabled     : True
description : Production Intune tenant for Win11 deployment

id          : 2
name        : MECM Primary Site
type        : MECM
enabled     : True
description : MECM CB 2309 primary site server

id          : 4
name        : Custom ITSM Publisher
type        : Generic
enabled     : True
description : Publishes packages to internal ITSM platform

Example 2 -- Get a specific connector by ID

Get-JuribaAppRIntegrationConnector -ConnectorId 1
Sample output 
id          : 1
name        : Intune Production
type        : Intune
enabled     : True
description : Production Intune tenant for Win11 deployment

Example 3 -- Filter connectors by type

Get-JuribaAppRIntegrationConnector | Where-Object { $_.type -eq 'Generic' }
Sample output 
id          : 4
name        : Custom ITSM Publisher
type        : Generic
enabled     : True
description : Publishes packages to internal ITSM platform
Note: The API endpoints used are api/integration/integrationConnector/list (all connectors) and api/integration/integrationConnector/{id} (single connector). The connector ID is distinct from the provider ID used by publishing property endpoints.

Get-JuribaAppRPublishingProperty

Synopsis

Gets publishing properties and templates from Juriba App Readiness.

Description

Publishing properties define the configurable fields for a publishing template. Each integration provider (Intune, MECM, or a generic integration) has its own set of properties that control how a package is published -- for example, the Intune display name override, detection rules, or MECM distribution point group. Properties can be scoped by provider and further filtered by package type. This cmdlet supports four retrieval modes depending on which parameters are supplied.

Syntax

# Mode 1: Get all publishing properties
Get-JuribaAppRPublishingProperty

# Mode 2: Get a specific property by ID
Get-JuribaAppRPublishingProperty -PropertyId <Int32>

# Mode 3: Get properties for a provider
Get-JuribaAppRPublishingProperty -ProviderId <Int32>

# Mode 4: Get properties for a provider filtered by package type
Get-JuribaAppRPublishingProperty -ProviderId <Int32> -PackageType <String>

Parameters

ParameterTypeStatusDescription
-Instance String Optional The URL of the App Readiness instance. Not required if connected via Connect-JuribaAppR.
-APIKey String Optional The API key for authentication. Not required if connected via Connect-JuribaAppR.
-PropertyId Int32 Optional The unique identifier of a specific publishing property. When specified, returns only that property.
-ProviderId Int32 Optional The integration provider ID. Filters properties to those belonging to the specified provider.
-PackageType String Optional The package type to filter by (e.g. Msi, IntuneWin, AppAttach). Only used in combination with -ProviderId.

Publishing Templates

A publishing template is the combination of a provider and its configured properties for a given package type. Templates define the default values and required fields that are sent along with a publish request. For example, an Intune IntuneWin template might include properties for the application category, owner, and detection rule type. When you call Invoke-JuribaAppRPublishGeneric with the Simple parameter set, the cmdlet automatically fetches the relevant template properties and populates the request body.

When to Use

Use this cmdlet to inspect what properties are available for a publishing template before triggering a publish. This is especially useful when building the -Properties hashtable for Invoke-JuribaAppRPublishGeneric, as you need the property IDs as keys. It is also valuable for documentation, auditing which templates are configured, and validating provider setup.

Invoke-JuribaAppRPublishIntune

Synopsis

Publishes a package to Microsoft Intune.

Description

Triggers the publishing of a completed package to a Microsoft Intune tenant configured as an integration connector. The request body is a hashtable that must include the application ID and package type, along with any Intune-specific properties defined in the publishing template. This cmdlet supports ShouldProcess, so you can use -WhatIf or -Confirm to preview the operation before execution.

Syntax

Invoke-JuribaAppRPublishIntune -Body <Hashtable> [-WhatIf] [-Confirm]

Parameters

ParameterTypeStatusDescription
-Instance String Optional The URL of the App Readiness instance. Not required if connected via Connect-JuribaAppR.
-APIKey String Optional The API key for authentication. Not required if connected via Connect-JuribaAppR.
-Body Hashtable Required A hashtable containing the publishing configuration. Must include applicationId and packageType. May also include publishing template properties specific to the Intune connector.

When to Use

Use this cmdlet when you want to publish a packaged application directly to Intune. This is typically the last step in an automated pipeline after the application has been packaged, tested, and passed quality review. It is designed for Intune-specific publishing; for MECM targets use Invoke-JuribaAppRPublishMECM, and for custom endpoints use Invoke-JuribaAppRPublishGeneric.

Examples

Example 1 -- Publish an IntuneWin package to Intune

$body = @{
    applicationId = 42
    packageType   = "IntuneWin"
}
Invoke-JuribaAppRPublishIntune -Body $body
Sample output 
publishingId : 1087
status       : Queued
applicationId: 42
packageType  : IntuneWin
target       : Intune Production
createdDate  : 2026-04-01T09:30:15Z

Example 2 -- Publish with additional template properties

$body = @{
    applicationId = 42
    packageType   = "IntuneWin"
    properties    = @(
        @{ id = 1; value = "Productivity" }
        @{ id = 2; value = "IT Operations" }
    )
}
Invoke-JuribaAppRPublishIntune -Body $body
Sample output 
publishingId : 1088
status       : Queued
applicationId: 42
packageType  : IntuneWin
target       : Intune Production
createdDate  : 2026-04-01T09:31:02Z

Example 3 -- Preview with -WhatIf

Invoke-JuribaAppRPublishIntune -Body @{ applicationId = 42; packageType = "IntuneWin" } -WhatIf
Sample output 
What if: Performing the operation "Publish to Intune" on target "App 42 (IntuneWin)".

Example 4 -- Real-world pipeline: QR check then publish

# Verify QR passed, then publish to Intune
$qr = Get-JuribaAppRQualityReview -AppId 42
if ($qr.QRStatus -eq 'Passed') {
    $body = @{
        applicationId = 42
        packageType   = "IntuneWin"
        properties    = @(
            @{ id = 1; value = "Productivity" }
            @{ id = 2; value = "IT Operations" }
        )
    }
    $result = Invoke-JuribaAppRPublishIntune -Body $body
    Write-Host "Publishing queued: ID $($result.publishingId)"
} else {
    Write-Warning "App 42 has not passed QR (status: $($qr.QRStatus))"
}
Sample output 
Publishing queued: ID 1089
Note: The -Body hashtable is sent as JSON to POST api/publishing/intune. The applicationId and packageType fields are required; any additional keys depend on the publishing template configured for your Intune connector. Use Get-JuribaAppRPublishingProperty to discover available property IDs.

Invoke-JuribaAppRPublishMECM

Synopsis

Publishes a package to Microsoft Endpoint Configuration Manager (MECM/SCCM).

Description

Triggers the publishing of a completed package to a MECM site server configured as an integration connector. The request body follows the same pattern as Intune publishing: a hashtable containing the application ID, package type, and any MECM-specific template properties. This cmdlet supports ShouldProcess for -WhatIf and -Confirm.

Syntax

Invoke-JuribaAppRPublishMECM -Body <Hashtable> [-WhatIf] [-Confirm]

Parameters

ParameterTypeStatusDescription
-Instance String Optional The URL of the App Readiness instance. Not required if connected via Connect-JuribaAppR.
-APIKey String Optional The API key for authentication. Not required if connected via Connect-JuribaAppR.
-Body Hashtable Required A hashtable containing the publishing configuration. Must include applicationId and packageType. May also include publishing template properties specific to the MECM connector.

When to Use

Use this cmdlet when your deployment target is MECM rather than Intune. The workflow is identical to Intune publishing -- build a body hashtable with the application ID, package type, and optional template properties, then invoke the cmdlet. For organizations that use both Intune and MECM, you can publish the same application to both targets in sequence.

Examples

Example 1 -- Publish an MSI package to MECM

Invoke-JuribaAppRPublishMECM -Body @{
    applicationId = 42
    packageType   = "Msi"
}
Sample output 
publishingId : 2041
status       : Queued
applicationId: 42
packageType  : Msi
target       : MECM Primary Site
createdDate  : 2026-04-01T10:15:33Z

Example 2 -- Publish with MECM-specific properties

$body = @{
    applicationId = 105
    packageType   = "Msi"
    properties    = @(
        @{ id = 10; value = "All Desktop Systems" }
        @{ id = 11; value = "\\mecm-dp\Content$" }
    )
}
Invoke-JuribaAppRPublishMECM -Body $body
Sample output 
publishingId : 2042
status       : Queued
applicationId: 105
packageType  : Msi
target       : MECM Primary Site
createdDate  : 2026-04-01T10:16:08Z

Example 3 -- Publish to both Intune and MECM

# Dual publish: IntuneWin to Intune, MSI to MECM
Invoke-JuribaAppRPublishIntune -Body @{ applicationId = 42; packageType = "IntuneWin" }
Invoke-JuribaAppRPublishMECM   -Body @{ applicationId = 42; packageType = "Msi" }

Write-Host "Application 42 queued for both Intune and MECM."
Sample output 
Application 42 queued for both Intune and MECM.
Note: The body is posted to POST api/publishing/mecm. MECM publishing requires that the MECM connector is configured with valid site server credentials and network access to the distribution point infrastructure.

Invoke-JuribaAppRPublishGeneric

Synopsis

Publishes a package to a generic integration endpoint.

Description

Triggers the publishing of a completed package to a configured generic integration. This cmdlet offers two parameter sets:

  • Simple (default) -- You provide -ApplicationId, -IntegrationId, and -PackageType. The cmdlet automatically fetches the application name, install/uninstall command lines, and the integration's publishing template properties, then assembles the full request body for you.
  • RawBody -- You provide a complete -Body hashtable. The cmdlet sends it directly with no auto-population. This is useful for advanced or legacy scenarios where you need full control over the payload.

The Simple parameter set also accepts an optional -Properties hashtable to override specific template property values, and an optional -Prerequisites array for dependency definitions. This cmdlet supports ShouldProcess.

Syntax

# Simple parameter set (auto-populates body)
Invoke-JuribaAppRPublishGeneric
    -ApplicationId <Int32>
    -IntegrationId <Int32>
    -PackageType <String>
    [-Properties <Hashtable>]
    [-Prerequisites <Array>]
    [-WhatIf] [-Confirm]

# RawBody parameter set (sends body as-is)
Invoke-JuribaAppRPublishGeneric
    -Body <Hashtable>
    [-WhatIf] [-Confirm]

Parameters

ParameterTypeStatusDescription
-Instance String Optional The URL of the App Readiness instance. Not required if connected via Connect-JuribaAppR.
-APIKey String Optional The API key for authentication. Not required if connected via Connect-JuribaAppR.
-ApplicationId Int32 Required (Simple) The ID of the application to publish.
-IntegrationId Int32 Required (Simple) The ID of the generic integration to publish to.
-PackageType String Required (Simple) The package type to publish. Valid values: Msi, IntuneWin, Psadt, AppAttach.
-Properties Hashtable Optional (Simple) A hashtable of publishing template property values, keyed by property ID. Properties not included in this hashtable are sent with empty values. Use Get-JuribaAppRPublishingProperty to discover available property IDs.
-Prerequisites Array Optional (Simple) An array of prerequisite objects. Defaults to an empty array when omitted.
-Body Hashtable Required (RawBody) A complete request body hashtable. When provided, the cmdlet skips all auto-population and sends this body directly to the API.

Package Type Mapping

The -PackageType parameter accepts friendly names that are mapped to integer values in the API request body:

Friendly NameAPI Value
Msi0
IntuneWin4
AppAttach5
Psadt6

Auto-Population (Simple Parameter Set)

When using the Simple parameter set, the cmdlet performs the following steps before sending the request:

  1. Calls Get-JuribaAppRApplication -AppId $ApplicationId to retrieve the application name and command lines.
  2. Locates the install and uninstall command lines matching the specified package type from the application's ext.allCommandLines collection.
  3. Calls Get-JuribaAppRPublishingProperty -ProviderId $IntegrationId to fetch the integration's template properties.
  4. Builds a properties array from the template, using values from -Properties where provided and empty strings otherwise.
  5. Assembles the complete body with applicationId, integrationId, applicationName, installationProgram, uninstallationProgram, properties, packageType, and prerequisites.

When to Use

Use this cmdlet when publishing to a custom or third-party deployment system that has been configured as a generic integration in App Readiness. The Simple parameter set is recommended for most use cases because it handles the boilerplate of fetching application metadata and template properties. Use the RawBody parameter set when you need to send a payload that differs from the auto-populated structure, or when integrating with legacy scripts that already construct the body.

Examples

Example 1 -- Simple publish with auto-population

Invoke-JuribaAppRPublishGeneric -ApplicationId 1941 -IntegrationId 4 -PackageType Msi
Sample output 
publishingId : 3201
status       : Queued
applicationId: 1941
packageType  : 0
target       : Custom ITSM Publisher
createdDate  : 2026-04-01T11:00:44Z

Example 2 -- Simple publish with custom property values

# First, discover available properties for the integration
Get-JuribaAppRPublishingProperty -ProviderId 4

# Then publish with specific property overrides
Invoke-JuribaAppRPublishGeneric `
    -ApplicationId 1941 `
    -IntegrationId 4 `
    -PackageType Msi `
    -Properties @{
        3 = "English"
        5 = "OU=Desktops,DC=contoso,DC=com"
    }
Sample output 
publishingId : 3202
status       : Queued
applicationId: 1941
packageType  : 0
target       : Custom ITSM Publisher
createdDate  : 2026-04-01T11:02:18Z

Example 3 -- Simple publish with prerequisites

Invoke-JuribaAppRPublishGeneric `
    -ApplicationId 1941 `
    -IntegrationId 4 `
    -PackageType IntuneWin `
    -Prerequisites @(
        @{ applicationId = 1900; packageType = 4; name = ".NET 8 Runtime" }
    )
Sample output 
publishingId : 3203
status       : Queued
applicationId: 1941
packageType  : 4
target       : Custom ITSM Publisher
createdDate  : 2026-04-01T11:05:30Z

Example 4 -- RawBody for full control

$body = @{
    applicationId         = "1941"
    integrationId         = 4
    applicationName       = "Acme Viewer Pro"
    installationProgram   = "msiexec /i AcmeViewer.msi /qn"
    uninstallationProgram = "msiexec /x {GUID} /qn"
    properties            = @(
        @{ id = 3; value = "English" }
        @{ id = 5; value = "OU=Desktops,DC=contoso,DC=com" }
    )
    packageType           = 0
    prerequisites         = @()
}
Invoke-JuribaAppRPublishGeneric -Body $body
Sample output 
publishingId : 3204
status       : Queued
applicationId: 1941
packageType  : 0
target       : Custom ITSM Publisher
createdDate  : 2026-04-01T11:08:55Z

Example 5 -- Preview with -WhatIf

Invoke-JuribaAppRPublishGeneric -ApplicationId 1941 -IntegrationId 4 -PackageType Msi -WhatIf
Sample output 
What if: Performing the operation "Publish to generic integration" on target
"Acme Viewer Pro (App 1941, Msi) to integration 4".
Important: The Simple and RawBody parameter sets are mutually exclusive. If you provide -Body, the cmdlet ignores -ApplicationId, -IntegrationId, -PackageType, -Properties, and -Prerequisites. Conversely, if you use the Simple set, you must not provide -Body.
Note: Both parameter sets post to POST api/publishing/generic. When using the Simple set, ensure the application has been packaged for the specified package type and that command lines exist in the application record, otherwise the installationProgram and uninstallationProgram fields will be sent as empty strings.
