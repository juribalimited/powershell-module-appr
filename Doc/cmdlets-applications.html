Application Cmdlets

These cmdlets cover the full lifecycle of applications in App Readiness: querying, listing, monitoring status and events, updating properties, assigning ownership, overriding command lines, and deleting applications.

Get-JuribaAppRApplication

Retrieves application details from App Readiness. Supports three modes: list all applications (no parameters), full detail for a single application (-AppId), or basic detail only (-AppId -Basic).

Syntax

Get-JuribaAppRApplication
    [-AppId <Int32>]
    [-Basic]
    [-Instance <String>]
    [-APIKey <String>]

Parameters

Name Type Required Default Description
-AppId Int32 Optional None (returns all) The unique identifier of the application. If omitted, returns all applications.
-Basic Switch Optional False When specified with -AppId, returns only basic application information (name, vendor, version) without status, packages, or assignment data.
-Instance String Optional Current connection The URL of the App Readiness instance.
-APIKey String Optional Current connection The API key for authentication.

When to Use

Use this cmdlet when you need the full detail payload for a single application (packages, status, assignments). For browsing and filtering across many applications, prefer Get-JuribaAppRApplicationList which supports search queries and lightweight modes. Use -Basic when you only need the name and metadata without the heavier status and package data.

Examples

Example 1: List all applications

Get-JuribaAppRApplication | Format-Table id, name, vendor, version
Sample output 
  id name                       vendor              version
  -- ----                       ------              -------
  10 7-Zip 23.01                Igor Pavlov         23.01
  15 Google Chrome 120          Google LLC          120.0.6099.130
  22 Notepad++ 8.6              Notepad++ Team      8.6
  31 Adobe Reader DC 2024       Adobe Inc.          2024.001.20604
  45 VLC Media Player 3.0.20    VideoLAN            3.0.20

Example 2: Get full detail for a single application

Get-JuribaAppRApplication -AppId 15
Sample output 
id                  : 15
name                : Google Chrome 120
vendor              : Google LLC
version             : 120.0.6099.130
fileName            : GoogleChromeStandaloneEnterprise64.msi
fileSize            : 104857600
commandLine         : /qn /norestart
ownerId             : 5
ownerName           : Bob Kelly
status              : Packaging
currentStage        : Repackaging
outputFormatBitmask : 37
createdDate         : 2026-03-15T09:22:00Z
packages            : {...}

Example 3: Get basic information only

Get-JuribaAppRApplication -AppId 15 -Basic
Sample output 
id       : 15
name     : Google Chrome 120
vendor   : Google LLC
version  : 120.0.6099.130
fileName : GoogleChromeStandaloneEnterprise64.msi

Notes

  • Without -AppId, the cmdlet calls api/apm/applications. With -AppId, it calls api/apm/application/{id}. With -AppId -Basic, it calls api/apm/application/{id}/basic.
  • The full detail response can be large for applications with many packages. Use -Basic when you only need metadata.

Get-JuribaAppRApplicationList

Retrieves a filtered list of applications with support for search queries, user-scoped views, and lightweight result sets. This is the primary cmdlet for browsing applications.

Syntax

# Current user's applications (default)
Get-JuribaAppRApplicationList
    [-Instance <String>] [-APIKey <String>]

# Search by query
Get-JuribaAppRApplicationList -Query <String>
    [-Instance <String>] [-APIKey <String>]

# All users
Get-JuribaAppRApplicationList -AllUsers
    [-Instance <String>] [-APIKey <String>]

# All users, lightweight
Get-JuribaAppRApplicationList -AllUsers -Lite
    [-Instance <String>] [-APIKey <String>]

Parameters

Name Type Required Default Description
-Query String Optional None A search query to filter applications by name, vendor, or other attributes.
-AllUsers Switch Optional False When specified, returns applications across all users rather than just the current user.
-Lite Switch Optional False When specified with -AllUsers, returns a lightweight result set with minimal fields. Significantly faster for large inventories.
-Instance String Optional Current connection The URL of the App Readiness instance.
-APIKey String Optional Current connection The API key for authentication.

When to Use

Use this cmdlet for browsing and searching the application inventory. For instances with hundreds or thousands of applications, use -AllUsers -Lite to avoid downloading full detail for every record. The -Lite mode returns only IDs, names, vendors, and versions, which is enough for dashboards, reports, and lookup tables. Use -Query to find specific applications by name.

Examples

Example 1: List applications assigned to the current user

Get-JuribaAppRApplicationList | Format-Table id, name, vendor, status
Sample output 
  id name                       vendor              status
  -- ----                       ------              ------
  15 Google Chrome 120          Google LLC          Packaging
  22 Notepad++ 8.6              Notepad++ Team      Testing
  31 Adobe Reader DC 2024       Adobe Inc.          Quality Review

Example 2: Search for applications by name

Get-JuribaAppRApplicationList -Query "Chrome" | Format-Table id, name, version, status
Sample output 
  id name                       version            status
  -- ----                       -------            ------
  15 Google Chrome 120          120.0.6099.130     Packaging
  67 Google Chrome 119          119.0.6045.200     Published

Example 3: List all applications across all users

Get-JuribaAppRApplicationList -AllUsers | Format-Table id, name, ownerName, status
Sample output 
  id name                       ownerName       status
  -- ----                       ---------       ------
  10 7-Zip 23.01                Sarah Chen      Published
  15 Google Chrome 120          Bob Kelly       Packaging
  22 Notepad++ 8.6              Bob Kelly       Testing
  31 Adobe Reader DC 2024       Bob Kelly       Quality Review
  45 VLC Media Player 3.0.20    James Wright    Uploaded
  52 PuTTY 0.80                 Sarah Chen      Published
  58 Python 3.12.1              James Wright    Packaging

Example 4: Lightweight listing for large inventories

# Fast query - returns minimal fields, ideal for 500+ app inventories
$apps = Get-JuribaAppRApplicationList -AllUsers -Lite
Write-Host "Total applications: $($apps.Count)"
$apps | Select-Object -First 5 | Format-Table id, name, vendor
Sample output 
Total applications: 847

  id name                       vendor
  -- ----                       ------
  10 7-Zip 23.01                Igor Pavlov
  15 Google Chrome 120          Google LLC
  22 Notepad++ 8.6              Notepad++ Team
  31 Adobe Reader DC 2024       Adobe Inc.
  45 VLC Media Player 3.0.20    VideoLAN

Notes

  • API endpoints: api/apm/applications/user (default), api/apm/applications/query/{query}, api/apm/applications/listOfAppsV2/true, api/apm/applications/listOfAppsLite/true.
  • The query string is URL-encoded automatically.
  • -Lite requires -AllUsers. Using -Lite alone has no effect.

Get-JuribaAppRApplicationStatus

Retrieves the full workflow tracker for an application, showing the status of each stage in the App Readiness pipeline. This is the primary cmdlet for monitoring an application's progress from upload through to publishing.

Syntax

Get-JuribaAppRApplicationStatus -AppId <Int32>
    [-Instance <String>] [-APIKey <String>]

Parameters

Name Type Required Default Description
-AppId Int32 Required None The unique identifier of the application.
-Instance String Optional Current connection The URL of the App Readiness instance.
-APIKey String Optional Current connection The API key for authentication.

Workflow Stages

The tracker returns an array of stage objects. Each stage includes a name, status, and progress percentage. The typical pipeline stages are:

  1. Upload -- Source installer uploaded and validated.
  2. Discovery -- Installer analyzed; metadata extracted.
  3. Repackaging -- Application captured and converted to target formats.
  4. Testing -- Automated smoke test on a clean VM.
  5. Quality Review -- Manual or automated quality gate.
  6. UAT -- User acceptance testing.
  7. Publishing -- Output packages deployed to Intune, MECM, or storage.

The currentProgressPercent field on the response object indicates overall progress across all stages (0--100).

When to Use

Use this cmdlet in polling loops to wait for packaging or testing to complete, or in dashboards to display the current state of each application in the pipeline.

Examples

Example 1: Check status of an application

Get-JuribaAppRApplicationStatus -AppId 15
Sample output 
appId                  : 15
appName                : Google Chrome 120
currentProgressPercent : 42
stages                 : {@{name=Upload; status=Complete; percent=100},
                          @{name=Discovery; status=Complete; percent=100},
                          @{name=Repackaging; status=InProgress; percent=65},
                          @{name=Testing; status=Pending; percent=0},
                          @{name=Quality Review; status=Pending; percent=0},
                          @{name=UAT; status=Pending; percent=0},
                          @{name=Publishing; status=Pending; percent=0}}

Example 2: Poll until packaging completes

do {
    $tracker = Get-JuribaAppRApplicationStatus -AppId 15
    $repack = $tracker.stages | Where-Object { $_.name -eq "Repackaging" }
    Write-Host "Repackaging: $($repack.status) ($($repack.percent)%)"
    if ($repack.status -ne "Complete") { Start-Sleep -Seconds 30 }
} while ($repack.status -notin @("Complete", "Failed"))

Write-Host "Repackaging finished with status: $($repack.status)"

Example 3: Display stages as a table

$tracker = Get-JuribaAppRApplicationStatus -AppId 22
$tracker.stages | Format-Table name, status, percent
Sample output 
name            status      percent
----            ------      -------
Upload          Complete        100
Discovery       Complete        100
Repackaging     Complete        100
Testing         Complete        100
Quality Review  InProgress       50
UAT             Pending           0
Publishing      Pending           0

Notes

  • Calls api/apm/application/{id}/tracker/full.
  • Stage statuses include Pending, InProgress, Complete, Failed, and Skipped.
  • The currentProgressPercent is a weighted average across all stages, not a simple count.

Get-JuribaAppRApplicationEvent

Retrieves the event history log for an application, showing all actions and status changes. Useful for auditing, troubleshooting failures, and extracting timing data for reports.

Syntax

Get-JuribaAppRApplicationEvent -AppId <Int32>
    [-Instance <String>] [-APIKey <String>]

Parameters

Name Type Required Default Description
-AppId Int32 Required None The unique identifier of the application.
-Instance String Optional Current connection The URL of the App Readiness instance.
-APIKey String Optional Current connection The API key for authentication.

When to Use

Use this cmdlet to audit what happened to an application, determine how long each stage took, or diagnose why a step failed. The event log is append-only and includes system-generated events (status transitions) as well as user actions (owner changes, retries).

Examples

Example 1: View all events for an application

Get-JuribaAppRApplicationEvent -AppId 15 | Format-Table eventDate, eventType, description -AutoSize
Sample output 
eventDate                eventType          description
---------                ---------          -----------
2026-03-15T09:22:00Z     Created            Application created by Bob Kelly
2026-03-15T09:22:05Z     FileUploaded       GoogleChromeStandaloneEnterprise64.msi uploaded (100 MB)
2026-03-15T09:23:12Z     DiscoveryComplete  Installer analysis completed - MSI detected
2026-03-15T09:25:00Z     RepackagingStarted Repackaging started on Win10-22H2-Packaging
2026-03-15T09:38:44Z     RepackagingComplete MSI, MSIX, IntuneWin packages created
2026-03-15T09:39:00Z     TestingStarted     Smoke test started on Win11-23H2-SmokeTest

Example 2: Filter events by date range

$events = Get-JuribaAppRApplicationEvent -AppId 15
$today = (Get-Date).Date
$events | Where-Object {
    [datetime]$_.eventDate -ge $today
} | Format-Table eventDate, eventType, description
Sample output 
eventDate                eventType          description
---------                ---------          -----------
2026-04-01T08:15:00Z     TestingComplete    Smoke test passed - all checks green
2026-04-01T08:15:05Z     QualityReviewStarted Quality review assigned to Sarah Chen

Example 3: Calculate time spent in repackaging

$events = Get-JuribaAppRApplicationEvent -AppId 15
$start = $events | Where-Object { $_.eventType -eq "RepackagingStarted" } | Select-Object -First 1
$end   = $events | Where-Object { $_.eventType -eq "RepackagingComplete" } | Select-Object -First 1
$duration = [datetime]$end.eventDate - [datetime]$start.eventDate
Write-Host "Repackaging took $($duration.TotalMinutes.ToString('N1')) minutes"

Notes

  • Calls api/apm/application/{id}/events.
  • Events are returned in chronological order.
  • Event dates are in UTC. Convert to local time with [datetime]::Parse($e.eventDate).ToLocalTime() if needed.

Set-JuribaAppRApplication

Updates the basic properties of an application using a hashtable of key-value pairs. Use this to rename an application, correct metadata, or update any editable attribute exposed by the API.

Syntax

Set-JuribaAppRApplication -AppId <Int32> -Body <Hashtable>
    [-Instance <String>] [-APIKey <String>]
    [-WhatIf] [-Confirm]

Parameters

Name Type Required Default Description
-AppId Int32 Required None The unique identifier of the application to update.
-Body Hashtable Required None A hashtable of properties to update. Keys must match the API schema (e.g., name, vendor, version).
-Instance String Optional Current connection The URL of the App Readiness instance.
-APIKey String Optional Current connection The API key for authentication.
-WhatIf Switch Optional False Shows what would happen without making the change.
-Confirm Switch Optional False Prompts for confirmation before making the change.

When to Use

Use this cmdlet to correct or override application metadata after upload. Common scenarios include renaming an application when the installer's embedded name is incorrect, updating the vendor field for consistency, or adjusting the version string.

Examples

Example 1: Rename an application

Set-JuribaAppRApplication -AppId 15 -Body @{ name = "Google Chrome Enterprise 120" }
Sample output 
id      : 15
name    : Google Chrome Enterprise 120
vendor  : Google LLC
version : 120.0.6099.130

Example 2: Update multiple properties

Set-JuribaAppRApplication -AppId 22 -Body @{
    name    = "Notepad++ 8.6.2"
    version = "8.6.2"
}

Example 3: Preview changes with -WhatIf

Set-JuribaAppRApplication -AppId 31 -Body @{ name = "Adobe Acrobat Reader DC" } -WhatIf
Sample output 
What if: Performing the operation "Update application properties" on target "App 31".

Notes

  • Calls api/apm/application/{id}/basic with a PUT request.
  • Supports ShouldProcess, so -WhatIf and -Confirm work as expected.
  • Only include properties you want to change in the -Body hashtable. Properties not included remain unchanged.

Set-JuribaAppRApplicationOwner

Assigns an owner to an application. Typically used to link the application to the requester from an external system such as ServiceNow or an ITSM integration.

Syntax

Set-JuribaAppRApplicationOwner -AppId <Int32> -UserId <Int32>
    [-Instance <String>] [-APIKey <String>]
    [-WhatIf] [-Confirm]

Parameters

Name Type Required Default Description
-AppId Int32 Required None The unique identifier of the application.
-UserId Int32 Required None The unique identifier of the user to assign as owner.
-Instance String Optional Current connection The URL of the App Readiness instance.
-APIKey String Optional Current connection The API key for authentication.
-WhatIf Switch Optional False Shows what would happen without making the change.
-Confirm Switch Optional False Prompts for confirmation before making the change.

When to Use

Use this after uploading an application to assign it to the correct packager or requester. The typical pattern is to look up the user ID first with Get-JuribaAppRUser, then pass it here.

Examples

Example 1: Look up a user and assign ownership

# Step 1: Find the target user
$users = Get-JuribaAppRUser -All
$packager = $users | Where-Object { $_.displayName -eq "Sarah Chen" }

# Step 2: Assign the application
Set-JuribaAppRApplicationOwner -AppId 45 -UserId $packager.userId
Write-Host "Application 45 assigned to $($packager.displayName)"
Sample output 
Application 45 assigned to Sarah Chen

Example 2: Direct assignment when user ID is known

Set-JuribaAppRApplicationOwner -AppId 15 -UserId 5

Example 3: Assign owner with confirmation prompt

Set-JuribaAppRApplicationOwner -AppId 31 -UserId 18 -Confirm
Sample output 
Confirm
Are you sure you want to perform this action?
Performing the operation "Assign owner User 18" on target "App 31".
[Y] Yes  [A] Yes to All  [N] No  [L] No to All  [S] Suspend  [?] Help (default is "Y"):

Notes

  • Calls api/apm/application/{appId}/owner/{userId} with a PUT request.
  • Supports ShouldProcess for -WhatIf and -Confirm.
  • The user must exist in App Readiness. Use Get-JuribaAppRUser -All to verify.

Set-JuribaAppRApplicationCommandLine

Sets a custom override command line for an application, replacing the automatically suggested installation command. Use this when the default silent switches are incorrect or when the requester specifies a particular installation configuration.

Syntax

Set-JuribaAppRApplicationCommandLine -AppId <Int32> -CommandLine <String>
    [-Instance <String>] [-APIKey <String>]
    [-WhatIf] [-Confirm]

Parameters

Name Type Required Default Description
-AppId Int32 Required None The unique identifier of the application.
-CommandLine String Required None The command line string to set for the application. This overrides any auto-detected command line.
-Instance String Optional Current connection The URL of the App Readiness instance.
-APIKey String Optional Current connection The API key for authentication.
-WhatIf Switch Optional False Shows what would happen without making the change.
-Confirm Switch Optional False Prompts for confirmation before making the change.

When to Use

Use this cmdlet when the auto-detected silent install flags are wrong, when you need to add custom MSI properties (e.g., ALLUSERS=1), or when the installer requires non-standard switches. Common scenarios include EXE installers that need vendor-specific silent flags, or MSI installers that need transform files applied.

Examples

Example 1: Set silent install flags for an EXE installer

Set-JuribaAppRApplicationCommandLine -AppId 10 -CommandLine "/S /v/qn"

Example 2: Apply MSI properties

Set-JuribaAppRApplicationCommandLine -AppId 31 -CommandLine "/qn ALLUSERS=1 TRANSFORMS=enterprise.mst /norestart"

Example 3: Preview the change before applying

Set-JuribaAppRApplicationCommandLine -AppId 15 -CommandLine "--system-level --silent" -WhatIf
Sample output 
What if: Performing the operation "Set command line to '--system-level --silent'" on target "App 15".

Notes

  • Calls api/apm/application/{id}/commandLine with a PUT request, sending { "commandLine": "..." } in the body.
  • Supports ShouldProcess for -WhatIf and -Confirm.
  • The command line is applied during the repackaging stage. Setting it after repackaging has completed has no effect unless the application is retried.
  • To revert to the auto-detected command line, set the value to an empty string.

Remove-JuribaAppRApplication

Permanently deletes an application and all associated data (packages, test results, events) from App Readiness.

Warning: Irreversible Operation

This action cannot be undone. All packages, test results, event history, and associated data will be permanently deleted. Always use -WhatIf first to verify you are targeting the correct application.

Syntax

Remove-JuribaAppRApplication -AppId <Int32>
    [-Instance <String>] [-APIKey <String>]
    [-WhatIf] [-Confirm]

Parameters

Name Type Required Default Description
-AppId Int32 Required None The unique identifier of the application to remove.
-Instance String Optional Current connection The URL of the App Readiness instance.
-APIKey String Optional Current connection The API key for authentication.
-WhatIf Switch Optional False Shows what would happen without actually removing the application.
-Confirm Switch Optional False Prompts for confirmation before removing. Enabled by default due to ConfirmImpact = 'High'.

When to Use

Use this cmdlet to clean up failed or duplicate applications. Because the ConfirmImpact is set to High, PowerShell will prompt for confirmation by default (unless $ConfirmPreference is set to None). Always verify the application ID with Get-JuribaAppRApplication -AppId before deleting.

Examples

Example 1: Preview deletion with -WhatIf

Remove-JuribaAppRApplication -AppId 67 -WhatIf
Sample output 
What if: Performing the operation "Remove application" on target "App 67".

Example 2: Delete an application (with automatic confirmation prompt)

Remove-JuribaAppRApplication -AppId 67
Sample output 
Confirm
Are you sure you want to perform this action?
Performing the operation "Remove application" on target "App 67".
[Y] Yes  [A] Yes to All  [N] No  [L] No to All  [S] Suspend  [?] Help (default is "Y"):

Example 3: Safe cleanup of duplicate applications

# Find duplicate Chrome entries
$dupes = Get-JuribaAppRApplicationList -Query "Chrome" |
    Where-Object { $_.status -eq "Failed" }

# Preview what will be removed
$dupes | ForEach-Object {
    Write-Host "Would remove: $($_.id) - $($_.name)"
    Remove-JuribaAppRApplication -AppId $_.id -WhatIf
}

# Actually remove after verification
$dupes | ForEach-Object {
    Remove-JuribaAppRApplication -AppId $_.id -Confirm:$false
}

Notes

  • Calls api/apm/application/{id} with a DELETE request.
  • The ConfirmImpact is High, which means PowerShell prompts for confirmation unless you pass -Confirm:$false or set $ConfirmPreference = 'None'.
  • There is no recycle bin or soft-delete. Once removed, the application and all its data are gone permanently.
  • Deletion may fail if the application is currently being processed (e.g., mid-repackaging). Wait for the current operation to complete or fail before retrying.
