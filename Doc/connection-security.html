Connection & Security

The Juriba.AppR module provides a secure connection model that stores credentials in memory as a SecureString so that subsequent cmdlets can authenticate automatically. This page covers the three cmdlets that manage that lifecycle: connecting, storing keys, and disconnecting.

Connect-JuribaAppR

Establishes a persistent connection to a Juriba App Readiness instance. Once connected, all other cmdlets in the module use the stored credentials automatically — you do not need to pass -Instance and -APIKey to every call.

Alias: Connect-AppR

Syntax

# Parameter set 1 — Plain text (default, least secure)
Connect-JuribaAppR
    -Instance <String>
    -APIKey <String>

# Parameter set 2 — SecureString
Connect-JuribaAppR
    -Instance <String>
    -SecureAPIKey <SecureString>

# Parameter set 3 — SecretManagement (recommended)
Connect-JuribaAppR
    -Instance <String>
    -SecretName <String>
    [-VaultName <String>]

Parameters

Name Type Required Default Description
-Instance String Required — The full URL of the Juriba App Readiness instance (e.g. https://appr.example.com). A trailing slash is automatically removed.
-APIKey String Required (PlainText set) — The API key as a plain text string. Accepted for interactive use and backward compatibility. Avoid in saved scripts — the key will be visible in your console history.
-SecureAPIKey SecureString Required (SecureString set) — The API key as a SecureString. Use with Read-Host -AsSecureString for interactive prompts that never expose the key in console history.
-SecretName String Required (SecretManagement set) — The name of a secret stored in a PowerShell SecretManagement vault. Requires the Microsoft.PowerShell.SecretManagement module and at least one registered vault. Use Set-JuribaAppRAPIKey to store the key first.
-VaultName String Optional Default vault The name of the SecretManagement vault to retrieve the secret from. If omitted, the default vault is used.

When to Use

Call Connect-JuribaAppR once at the start of your session or script. All subsequent cmdlets (Get-JuribaAppRApplication, Start-JuribaAppRPipeline, etc.) will authenticate using the stored connection. This eliminates the need to pass -Instance and -APIKey on every call and avoids scattering credentials throughout your code.

Connection Validation

When you call Connect-JuribaAppR, the cmdlet does not simply store credentials — it actively validates them by making an HTTP GET request to the /api/packaging/upload/packageTypesMatrix endpoint. If the API key is invalid or expired, the server typically returns an HTML page (the Angular SPA) instead of JSON. The cmdlet detects this and throws a clear error rather than allowing silent failures later.

Warning: Avoid passing API keys as plain text strings in saved scripts. The key will appear in your PowerShell console history (Get-History) and may be logged by transcription or auditing tools. Use the -SecretName parameter set for automation, or -SecureAPIKey with Read-Host -AsSecureString for interactive sessions.

Examples

Example 1: Connect using SecretManagement (recommended)

Retrieves the API key from a SecretManagement vault by name. This is the most secure approach and is ideal for automation, shared scripts, and CI/CD pipelines. 

Connect-JuribaAppR -Instance "https://appr.juriba.com" -SecretName "AppR-Production"
Sample Output 
Connected to Juriba App Readiness at https://appr.juriba.com

Example 2: Connect using a specific vault

When you have multiple vaults registered (e.g. one per team or environment), specify the vault explicitly. 

Connect-JuribaAppR -Instance "https://appr-staging.juriba.com" `
    -SecretName "AppR-Staging" `
    -VaultName "CompanyVault"
Sample Output 
Connected to Juriba App Readiness at https://appr-staging.juriba.com

Example 3: Connect with a SecureString prompt

Prompts for the API key interactively. The key is masked in the console and never stored in history. 

$secure = Read-Host "Enter API Key" -AsSecureString
Connect-JuribaAppR -Instance "https://appr.juriba.com" -SecureAPIKey $secure
Sample Output 
Enter API Key: ************
Connected to Juriba App Readiness at https://appr.juriba.com

Example 4: Connect with a plain text key (interactive use only)

Acceptable for one-off interactive testing. Do not use this approach in saved scripts or automation. 

Connect-JuribaAppR -Instance "https://appr.juriba.com" -APIKey "WeBP5sp+eQxOi7JYfiRq3t..."
Sample Output 
Connected to Juriba App Readiness at https://appr.juriba.com

Example 5: Handling a failed connection

If the instance URL or API key is incorrect, the cmdlet throws a terminating error. 

try {
    Connect-JuribaAppR -Instance "https://appr.juriba.com" -APIKey "invalid-key"
}
catch {
    Write-Error "Connection failed: $_"
}
Sample Output 
Write-Error: Connection failed: Failed to connect to 'https://appr.juriba.com'.
Please verify the instance URL and API key.
Error: API key authentication failed - server returned HTML instead of JSON.
The API key may be invalid or expired.

Notes

  • The connection is stored in the $global:appRConnection variable and persists for the lifetime of the PowerShell session.
  • Even when you supply a plain text key, it is immediately converted to a SecureString in memory and the plain text reference is cleared.
  • The cmdlet validates the connection at call time. If the API key is later revoked or expires, subsequent requests will fail individually.

Set-JuribaAppRAPIKey

Stores an App Readiness API key in a PowerShell SecretManagement vault. This is a one-time setup step. After storing the key, use Connect-JuribaAppR -SecretName to connect without ever exposing the key in your scripts.

Syntax

# Parameter set 1 — Plain text input
Set-JuribaAppRAPIKey
    -SecretName <String>
    -APIKey <String>
    [-VaultName <String>]

# Parameter set 2 — SecureString input
Set-JuribaAppRAPIKey
    -SecretName <String>
    -SecureAPIKey <SecureString>
    [-VaultName <String>]

Parameters

Name Type Required Default Description
-SecretName String Required — The name to store the secret under. Use a descriptive name like "AppR-Production" or "AppR-Staging" so it is clear which instance the key belongs to.
-APIKey String Required (PlainText set) — The API key as a plain text string. It will be stored encrypted in the vault. The plain text is cleared from memory immediately after storage.
-SecureAPIKey SecureString Required (SecureString set) — The API key as a SecureString. Preferred for interactive use — combine with Read-Host -AsSecureString to avoid exposing the key.
-VaultName String Optional Default vault The vault to store the secret in. If omitted, the default vault is used.

When to Use

Run this cmdlet once per environment to store an API key securely. After that, your scripts only reference the secret by name — the actual key never appears in source code, console history, or log files. This is especially important for:

  • Automation scripts checked into version control
  • Shared scripts used by multiple team members
  • CI/CD pipelines where secrets are injected at runtime

One-Time Vault Setup

If you do not yet have a SecretManagement vault configured, run these commands once to set up the built-in SecretStore provider: 

# Install the SecretManagement framework and the local SecretStore provider
Install-Module Microsoft.PowerShell.SecretManagement -Scope CurrentUser
Install-Module Microsoft.PowerShell.SecretStore -Scope CurrentUser

# Register a default vault
Register-SecretVault -Name "Default" -ModuleName Microsoft.PowerShell.SecretStore -DefaultVault

The SecretStore provider encrypts secrets on disk using the current user's credentials. For enterprise scenarios, you can register an Azure Key Vault or other provider instead.

Examples

Example 1: Store a key with plain text input

Stores the API key in the default vault. After this, the plain text key is no longer needed in your scripts. 

Set-JuribaAppRAPIKey -SecretName "AppR-Production" -APIKey "WeBP5sp+eQxOi7JYfiRq3tRGH..."
Sample Output 
API key stored as 'AppR-Production' in the default vault.
Connect with: Connect-JuribaAppR -Instance "https://..." -SecretName "AppR-Production"

Example 2: Store a key with a SecureString prompt

The key is masked as you type and never appears in the console. This is the safest way to store a key interactively. 

Set-JuribaAppRAPIKey -SecretName "AppR-Staging" -SecureAPIKey (Read-Host "API Key" -AsSecureString)
Sample Output 
API Key: ************
API key stored as 'AppR-Staging' in the default vault.
Connect with: Connect-JuribaAppR -Instance "https://..." -SecretName "AppR-Staging"

Example 3: Store a key in a specific vault

Useful when you have separate vaults for different teams or security boundaries. 

Set-JuribaAppRAPIKey -SecretName "AppR-Dev" -APIKey $key -VaultName "TeamVault"
Sample Output 
API key stored as 'AppR-Dev' in vault 'TeamVault'.
Connect with: Connect-JuribaAppR -Instance "https://..." -SecretName "AppR-Dev"

Notes

  • This cmdlet is a convenience wrapper around Set-Secret from the SecretManagement module. You can also call Set-Secret directly if you prefer.
  • If the SecretManagement module is not installed, the cmdlet throws a descriptive error with the exact installation commands.
  • Plain text key values are cleared from memory ($null) in a finally block immediately after storage.

Disconnect-JuribaAppR

Clears the stored connection credentials established by Connect-JuribaAppR. After disconnecting, all cmdlets will require explicit -Instance and -APIKey parameters.

Alias: Disconnect-AppR

Syntax

Disconnect-JuribaAppR

Parameters

This cmdlet has no parameters.

When to Use

Call Disconnect-JuribaAppR when you need to switch to a different instance, rotate credentials within a session, or clean up after a script completes. It removes the $global:appRConnection variable, including the SecureString API key stored in memory.

Examples

Example 1: Disconnect from the current instance

Disconnect-JuribaAppR
Sample Output 
Disconnected from Juriba App Readiness at https://appr.juriba.com

Example 2: Using the alias

Disconnect-AppR
Sample Output 
Disconnected from Juriba App Readiness at https://appr.juriba.com

Example 3: Switch between instances

Disconnect from one instance and immediately connect to another. 

# Disconnect from production
Disconnect-JuribaAppR

# Connect to staging
Connect-JuribaAppR -Instance "https://appr-staging.juriba.com" -SecretName "AppR-Staging"
Sample Output 
Disconnected from Juriba App Readiness at https://appr.juriba.com
Connected to Juriba App Readiness at https://appr-staging.juriba.com

Example 4: Disconnect when no connection exists

Disconnect-JuribaAppR
Sample Output 
WARNING: No active App Readiness connection to disconnect.

Notes

  • If no connection is active, the cmdlet emits a warning rather than throwing an error. This makes it safe to call unconditionally in cleanup blocks.
  • Disconnecting does not revoke the API key — it only removes it from the current PowerShell session's memory.

Best Practices

Never hardcode API keys

API keys in source code are a security risk. They can leak through version control history, log files, shared terminals, and PowerShell transcription. Always use one of the secure approaches described above.

Do not do this: 
# BAD - key is visible in source code, console history, and version control
Connect-JuribaAppR -Instance "https://appr.juriba.com" -APIKey "WeBP5sp+eQxOi7JYfiRq3t..."
Do this instead: 
# GOOD - key is stored encrypted and referenced by name
Connect-JuribaAppR -Instance "https://appr.juriba.com" -SecretName "AppR-Production"

Use SecretManagement for automation

For unattended scripts, scheduled tasks, and CI/CD pipelines, the SecretManagement approach is the only option that avoids exposing keys. The typical workflow is:

  1. One-time setup (interactive, on the machine that will run the script): 
    Set-JuribaAppRAPIKey -SecretName "AppR-Production" -SecureAPIKey (Read-Host "Key" -AsSecureString)
  2. In your script (no secrets in code): 
    Connect-JuribaAppR -Instance "https://appr.juriba.com" -SecretName "AppR-Production"
# ... rest of your automation ...

Use per-environment keys

Store separate secrets for each environment using descriptive names. This prevents accidentally running a production script against a staging instance (or vice versa). 

# Store keys for each environment
Set-JuribaAppRAPIKey -SecretName "AppR-Production" -SecureAPIKey (Read-Host "Prod Key" -AsSecureString)
Set-JuribaAppRAPIKey -SecretName "AppR-Staging"    -SecureAPIKey (Read-Host "Staging Key" -AsSecureString)
Set-JuribaAppRAPIKey -SecretName "AppR-Dev"        -SecureAPIKey (Read-Host "Dev Key" -AsSecureString)

# Connect to the appropriate environment
$env = "Production"  # or from a config file / parameter
Connect-JuribaAppR -Instance "https://appr.juriba.com" -SecretName "AppR-$env"

How the connection works internally

Understanding the internals helps with troubleshooting and explains why the module behaves the way it does.

  1. Key resolution: Regardless of which parameter set you use (plain text, SecureString, or SecretManagement), the cmdlet resolves the input to a plain text key temporarily for the validation request.
  2. Validation: An HTTP GET request is made to /api/packaging/upload/packageTypesMatrix with the API key in the x-api-key header. The cmdlet checks that the response is JSON (not the Angular SPA HTML fallback that indicates an authentication failure).
  3. Storage: The key is converted to a SecureString and stored in $global:appRConnection alongside the instance URL and connection timestamp. The plain text key reference is immediately set to $null.
  4. Usage: Other cmdlets in the module check for $global:appRConnection. If present, they extract the instance URL and decrypt the SecureString for each API call. If absent, they require -Instance and -APIKey as explicit parameters.
  5. Cleanup: Disconnect-JuribaAppR removes the global variable, releasing the SecureString from memory.

The $global:appRConnection hashtable contains the following keys:

Key Type Description
Instance String The base URL of the connected instance (trailing slash removed).
SecureAPIKey SecureString The API key encrypted in memory. Never stored as plain text.
ConnectedAt DateTime The timestamp when the connection was established.
