Upload & Create Cmdlets

These cmdlets handle the full lifecycle of getting an installer into App Readiness and creating an application from it: chunked upload, application creation with metadata and command detection, and polling until the workflow reaches a terminal state.

Send-JuribaAppRSetupFile

Uploads a setup file (MSI, EXE, ZIP, or any supported installer) to App Readiness using chunked upload. The file is split into configurable chunks, uploaded individually, and combined server-side. Returns an object containing the upload UUID and file metadata needed by New-JuribaAppRApplication.

Syntax

Send-JuribaAppRSetupFile
    -FilePath <String>
    [-Instance <String>]
    [-APIKey <String>]
    [-ChunkSizeMB <Int32>]
    [-Protected]

Parameters

ParameterTypeStatusDescription
-FilePathStringRequiredFull path to the setup file to upload. The file must exist on disk.
-InstanceStringOptionalInstance URL. Not required if connected via Connect-JuribaAppR.
-APIKeyStringOptionalAPI key. Not required if connected via Connect-JuribaAppR.
-ChunkSizeMBInt32OptionalSize of each upload chunk in megabytes. Default: 2. Valid range: 1-100. Increase for faster uploads on high-bandwidth connections.
-ProtectedSwitchOptionalUploads to the protected endpoint for files requiring additional security handling.

Return Object

The cmdlet returns a PSCustomObject with the following properties:

PropertyTypeDescription
UuidStringUnique upload identifier. Pass this to New-JuribaAppRApplication.
FileNameStringOriginal file name of the uploaded file.
FileSizeInt64Size of the file in bytes.
TotalChunksInt32Number of chunks the file was split into.
NameStringProduct name extracted from the file's FileVersionInfo. May be $null for non-PE files.
ManufacturerStringCompany/manufacturer extracted from the file's FileVersionInfo.
VersionStringVersion extracted from the file's FileVersionInfo.

When to Use

  • Use -ChunkSizeMB when uploading large files (hundreds of MB or more) on a fast network to reduce the number of HTTP round-trips.
  • Use -Protected when uploading files that contain sensitive data or require elevated security handling on the server.

Examples

Example 1: Basic upload

$upload = Send-JuribaAppRSetupFile -FilePath "C:\Installers\Firefox-Setup-115.0.exe"
$upload
Sample Output 
Uuid           : a3f7c9e2-81d4-4b6a-9e02-5c8d1f3a7b60
FileName       : Firefox-Setup-115.0.exe
FileSize       : 56440320
TotalChunks    : 27
Name           : Firefox
Manufacturer   : Mozilla Corporation
Version        : 115.0

Example 2: Large file with custom chunk size

$upload = Send-JuribaAppRSetupFile -FilePath "C:\Installers\BigApp-Setup.exe" -ChunkSizeMB 10
$upload | Format-List Uuid, FileName, FileSize, TotalChunks
Sample Output

FileName    : BigApp-Setup.exe
FileSize    : 524288000
TotalChunks : 50
Note: Progress is reported via Write-Progress during the upload. Use -Verbose to see detailed chunk-by-chunk logging including byte offsets and the combine request.

New-JuribaAppRApplication

Creates a new application in App Readiness from a previously uploaded setup file. This is the most complex cmdlet in the module: it reads Default Settings from the instance, calls server-side metadata extraction, queries the command suggestion engine, and submits the creation request. The application is created asynchronously -- use Watch-JuribaAppRApplicationCreation to wait for the record to appear, then Watch-JuribaAppRApplicationStatus to track the packaging workflow.

Syntax

New-JuribaAppRApplication
    -Uuid <String>
    -FileName <String>
    -FileSize <Int64>
    -TotalChunks <Int32>
    [-Instance <String>]
    [-APIKey <String>]
    [-Name <String>]
    [-Manufacturer <String>]
    [-Version <String>]
    [-CommandLine <String>]
    [-RunImmediately]
    [-VMGroupId <Int32>]
    [-VMGroupForTestingId <Int32>]
    [-PrePackaged]
    [-SkipMetadataExtraction]
    [-SkipCommandSuggestion]

Parameters

ParameterTypeStatusDescription
-UuidStringRequiredUpload UUID returned by Send-JuribaAppRSetupFile.
-FileNameStringRequiredOriginal file name. Returned by Send-JuribaAppRSetupFile.
-FileSizeInt64RequiredFile size in bytes. Returned by Send-JuribaAppRSetupFile.
-TotalChunksInt32RequiredNumber of upload chunks. Returned by Send-JuribaAppRSetupFile.
-InstanceStringOptionalInstance URL override.
-APIKeyStringOptionalAPI key override.
-NameStringOptionalApplication name. When omitted, the server-side metadata extraction API detects it from the binary; if that fails, the file name (without extension) is used.
-ManufacturerStringOptionalManufacturer/vendor name. Falls back to server metadata, then "Unknown".
-VersionStringOptionalApplication version. Falls back to server metadata, then "1.0".
-CommandLineStringOptionalExplicit silent install command line. When omitted, the command suggestion API auto-detects it.
-RunImmediatelySwitchOptionalBegin automated packaging immediately after creation.
-VMGroupIdInt32OptionalVM group for packaging. Falls back to the instance's Default Settings.
-VMGroupForTestingIdInt32OptionalVM group for smoke testing. Falls back to the instance's Default Settings.
-PrePackagedSwitchOptionalIndicates the file is already a final package (e.g. MSI) that does not need repackaging.
-SkipMetadataExtractionSwitchOptionalSkips the server-side metadata extraction API call.
-SkipCommandSuggestionSwitchOptionalSkips the command suggestion API call.

When to Include Optional Parameters

ParameterWhen to include
-Name, -Manufacturer, -VersionWhen overriding server-side extraction -- for example, when the binary metadata is missing, incorrect, or you want a specific display name in App Readiness.
-CommandLineWhen you already know the correct silent install command and want to bypass the suggestion engine entirely.
-RunImmediatelyIn almost all automation scenarios. Without this flag, the application is created but sits idle until manually triggered.
-VMGroupId, -VMGroupForTestingIdWhen targeting a specific VM pool instead of the instance-wide defaults. Useful in multi-tenant or multi-environment setups.
-PrePackagedWhen uploading an already-packaged MSI that does not need repackaging. The file is imported directly as a finished package.
-SkipMetadataExtraction, -SkipCommandSuggestionWhen you provide all metadata and the command line explicitly, and want to avoid the extra API calls.

Wrapping vs Repackaging

The cmdlet automatically determines the packaging workflow based on your instance's Default Settings output format bitmask:

  • Repackaging (from=0): The installer is executed inside a VM and captured. Required when the output format includes MSI, MSIX, or MSIX App Attach. A VM group must be available.
  • Wrapping (from=4): The installer is wrapped into an output package without VM execution. Used when the output format only includes IntuneWin or PSADT. No VM is required.

You do not need to set this manually -- the cmdlet reads the bitmask from Default Settings and selects the correct workflow.

Command Suggestion Priority

When -CommandLine is not provided, the cmdlet calls the command suggestion API. The engine returns candidates from multiple sources, ranked by priority:

  1. Juriba Knowledge Base (source 3) -- commands proven successful across the Juriba customer base. Highest priority.
  2. Programmatic detection (source 1) -- rules-based detection from file naming conventions and installer type.
  3. AI-generated (source 2) -- machine-learning suggestions. Lowest priority, used as a fallback.

Within each source, the engine prefers commands with a previous success record (lastResult > 0), then ranks by success rate.

Examples

Example 1: Minimal -- auto-detect everything

$upload = Send-JuribaAppRSetupFile -FilePath "C:\Installers\7z2407-x64.exe"
$app = New-JuribaAppRApplication -Uuid $upload.Uuid -FileName $upload.FileName `
    -FileSize $upload.FileSize -TotalChunks $upload.TotalChunks -RunImmediately

Get-JuribaAppRApplicationCreationState

Polls the asynchronous creation state of an application. After calling New-JuribaAppRApplication, the application record is created in the background. Use this cmdlet to check whether creation has completed, is still in progress, or has failed.

Syntax

Get-JuribaAppRApplicationCreationState
    -UploadId <String>
    [-Instance <String>]
    [-APIKey <String>]

Parameters

ParameterTypeStatusDescription
-UploadIdStringRequiredThe upload UUID returned by Send-JuribaAppRSetupFile or New-JuribaAppRApplication.
-InstanceStringOptionalInstance URL override.
-APIKeyStringOptionalAPI key override.

When to Use

Use this cmdlet when you need a single point-in-time check of creation progress. For automated scripts that need to wait until creation finishes, prefer Watch-JuribaAppRApplicationCreation instead.

Examples

Example 1: Check creation state

Get-JuribaAppRApplicationCreationState -UploadId "a3f7c9e2-81d4-4b6a-9e02-5c8d1f3a7b60"
Sample Output -- In Progress 
status        : InProgress
applicationId : 0
message       :
Sample Output -- Completed 
status        : Completed
applicationId : 619
message       :
Sample Output -- Failed 
status  : Failed
applicationId : 0
message : Upload identifier not found or expired.
Note: This cmdlet calls GET api/apm/application/creation/{UploadId}/state. The creation state is distinct from the packaging workflow state -- it only tracks whether the application record itself has been written to the database.

Watch-JuribaAppRApplicationCreation

Polls the creation state of an application at a defined interval until it completes, fails, or times out. This is the blocking equivalent of repeatedly calling Get-JuribaAppRApplicationCreationState. Returns the final state object, which includes the applicationId on success.

Syntax

Watch-JuribaAppRApplicationCreation
    -UploadId <String>
    [-Instance <String>]
    [-APIKey <String>]
    [-IntervalSeconds <Int32>]
    [-TimeoutMinutes <Int32>]
    [-Quiet]

Parameters

ParameterTypeStatusDefaultDescription
-UploadIdStringRequired--Upload UUID from Send-JuribaAppRSetupFile.
-InstanceStringOptional--Instance URL override.
-APIKeyStringOptional--API key override.
-IntervalSecondsInt32Optional300Seconds between polls. Valid range: 10-3600.
-TimeoutMinutesInt32Optional120Maximum minutes to poll. Valid range: 1-1440.
-QuietSwitchOptional--Suppress console output; only return the final object.

When to Use

Use this in automation pipelines between New-JuribaAppRApplication and Watch-JuribaAppRApplicationStatus. Creation typically completes within a few minutes but can take longer under heavy server load. For quick interactive checks, Get-JuribaAppRApplicationCreationState is lighter weight.

Examples

$result = Watch-JuribaAppRApplicationCreation -UploadId $upload.Uuid

}

Watch-JuribaAppRApplicationStatus

Polls the full workflow status of an application until it reaches a terminal state or times out. Use this after the application has been created and is processing through the packaging, testing, and publishing pipeline.

Syntax

Watch-JuribaAppRApplicationStatus
    -AppId <Int32>
    [-Instance <String>]
    [-APIKey <String>]
    [-IntervalSeconds <Int32>]
    [-TimeoutMinutes <Int32>]
    [-Quiet]

Parameters

ParameterTypeStatusDefaultDescription
-AppIdInt32Required--The application ID to monitor.
-InstanceStringOptional--Instance URL override.
-APIKeyStringOptional--API key override.
-IntervalSecondsInt32Optional300Seconds between polls. Valid range: 10-3600.
-TimeoutMinutesInt32Optional240Maximum minutes to poll. Valid range: 1-1440.
-QuietSwitchOptional--Suppress console output; only return the final object.

Terminal States

The cmdlet stops polling when the application's ext.status reaches one of these values:

StateMeaning
ReadyForQualityReviewPackaging succeeded. The application is waiting for manual quality review.
QualityReviewQuality review is in progress.
ReadyForUatQuality review passed. Waiting for user acceptance testing.
UatUser acceptance testing is in progress.
ReadyForPublishingAll testing passed. Waiting for publishing.
PublishedThe application has been published to the target deployment system.
FailedThe workflow failed at some stage.
FailedPackagingPackaging specifically failed (e.g., VM error, installer crash).
FailedToPackageEquivalent to FailedPackaging in some API versions.
CancelledThe workflow was manually cancelled.

When to Use

Use this as the final step in an automation pipeline. Packaging can take anywhere from a few minutes (wrapping-only) to over an hour (full VM repackaging with testing). Adjust -IntervalSeconds and -TimeoutMinutes accordingly.

Example 1: Watch with default settings

$final = Watch-JuribaAppRApplicationStatus -AppId 619
