Generic Integration Cmdlets

Overview

The Generic Integration framework allows App Readiness to publish packages to custom or third-party distribution systems. Unlike the built-in Intune and MECM connectors, which handle the full publish lifecycle internally, a generic integration delegates the actual deployment work to an external script or service. App Readiness queues the publish request and exposes it through the Generic Integration API; your automation then polls for pending publishings, downloads the package, performs the deployment, logs progress, and reports the final state back.

Typical Flow

A generic integration publishing script typically follows this sequence:

  1. List integrations -- Call Get-JuribaAppRGenericIntegration to discover configured generic integrations and find your target integration ID.
  2. List pending publishings -- Call Get-JuribaAppRGenericIntegrationPublishing with the integration ID to retrieve the queue of publishing IDs waiting to be processed.
  3. Get properties -- For each publishing ID, call Get-JuribaAppRGenericIntegrationProperty to retrieve the application metadata, command lines, and template property values.
  4. Get prerequisites -- Call Get-JuribaAppRGenericIntegrationPrerequisite to retrieve any dependency information for the publishing.
  5. Download source -- Call Get-JuribaAppRGenericIntegrationSource to download the package file to a local directory.
  6. Deploy and log -- Perform your custom deployment logic. Use Add-JuribaAppRGenericIntegrationLog to record progress, warnings, or errors as the work proceeds.
  7. Update state -- Call Update-JuribaAppRGenericIntegrationPublishingState to mark the publishing as Succeeded or Failed.

Get-JuribaAppRGenericIntegration

Synopsis

Gets all generic integrations configured in Juriba App Readiness.

Description

Retrieves the collection of configured generic integrations. Each integration represents a custom publishing endpoint that has been registered in App Readiness. The returned objects include the integration ID, name, and configuration details needed to interact with the integration's publishing queue.

Syntax

Get-JuribaAppRGenericIntegration

Parameters

ParameterTypeStatusDescription
-Instance String Optional The URL of the App Readiness instance. Not required if connected via Connect-JuribaAppR.
-APIKey String Optional The API key for authentication. Not required if connected via Connect-JuribaAppR.

When to Use

Use this cmdlet at the start of a generic integration script to discover which integrations are available and to obtain the integration ID required by all subsequent generic integration cmdlets. It is also useful for inventory and configuration audit scripts.

Examples

Example 1 -- List all generic integrations

Get-JuribaAppRGenericIntegration
Sample output 
id          : 4
name        : Custom ITSM Publisher
description : Publishes packages to internal ITSM platform
enabled     : True

id          : 7
name        : Azure Blob Staging
description : Stages packages to Azure Blob for downstream pickup
enabled     : True

Example 2 -- Store integration ID for later use

$integrations = Get-JuribaAppRGenericIntegration
$itsmId = ($integrations | Where-Object { $_.name -eq 'Custom ITSM Publisher' }).id
Write-Host "ITSM integration ID: $itsmId"
Sample output 
ITSM integration ID: 4
Note: This cmdlet calls GET api/v1/integration/generic. It returns only generic integrations, not Intune or MECM connectors. To list all connector types, use Get-JuribaAppRIntegrationConnector instead.

Get-JuribaAppRGenericIntegrationPublishing

Synopsis

Gets publishing records for a generic integration.

Description

Retrieves the collection of publishing records queued for a specific generic integration. The records can be filtered by a maximum count and by package types. This is the cmdlet you call to discover which publishings are waiting to be processed by your external script.

Syntax

Get-JuribaAppRGenericIntegrationPublishing
    -IntegrationId <Int32>
    [-Limit <Int32>]
    [-PackageTypes <String>]

Parameters

ParameterTypeStatusDescription
-Instance String Optional The URL of the App Readiness instance. Not required if connected via Connect-JuribaAppR.
-APIKey String Optional The API key for authentication. Not required if connected via Connect-JuribaAppR.
-IntegrationId Int32 Required The unique identifier of the generic integration.
-Limit Int32 Optional Maximum number of publishing records to return. When omitted, all records are returned.
-PackageTypes String Optional Comma-separated list of package types to filter by (e.g. "Msi,AppV"). When omitted, all package types are returned.

When to Use

Use this cmdlet to poll the integration's publishing queue. A typical automation script calls this on a schedule (or as a triggered task) to check for new publishings that need processing. The returned IDs are then passed to Get-JuribaAppRGenericIntegrationProperty, Get-JuribaAppRGenericIntegrationPrerequisite, and Get-JuribaAppRGenericIntegrationSource to retrieve the full details and package file.

Examples

Example 1 -- Get all publishing records for an integration

Get-JuribaAppRGenericIntegrationPublishing -IntegrationId 4
Sample output 
3201
3202
3204
3207

Example 2 -- Get the last 5 MSI publishings

Get-JuribaAppRGenericIntegrationPublishing -IntegrationId 4 -Limit 5 -PackageTypes "Msi"
Sample output 
3201
3204

Example 3 -- Iterate over pending publishings

$publishingIds = Get-JuribaAppRGenericIntegrationPublishing -IntegrationId 4
foreach ($pubId in $publishingIds) {
    Write-Host "Processing publishing $pubId..."
    # Retrieve properties, download source, deploy, etc.
}
Sample output 
Processing publishing 3201...
Processing publishing 3202...
Processing publishing 3204...
Processing publishing 3207...
Important: The API returns an array of integer IDs, not full publishing objects. Each integer is a publishing ID that must be passed to the property, prerequisite, and source cmdlets to retrieve the full record. Do not expect object properties such as application name or status from this endpoint.

Get-JuribaAppRGenericIntegrationProperty

Synopsis

Gets properties for a specific publishing in a generic integration.

Description

Retrieves the collection of properties for a specific publishing record. These properties contain the application metadata, command lines, and any template property values that were set when the publish was triggered. This is the primary cmdlet for obtaining the details your deployment script needs to install or stage the package.

Syntax

Get-JuribaAppRGenericIntegrationProperty
    -IntegrationId <Int32>
    -PublishingId <Int32>

Parameters

ParameterTypeStatusDescription
-Instance String Optional The URL of the App Readiness instance. Not required if connected via Connect-JuribaAppR.
-APIKey String Optional The API key for authentication. Not required if connected via Connect-JuribaAppR.
-IntegrationId Int32 Required The unique identifier of the generic integration.
-PublishingId Int32 Required The unique identifier of the publishing record.

When to Use

Call this cmdlet after retrieving a publishing ID from Get-JuribaAppRGenericIntegrationPublishing. The returned properties give you the application name, install/uninstall commands, package type, and any custom template values. This information drives the logic in your deployment script -- for example, which command line to execute, what target OU to deploy to, or what metadata to register in your downstream system.

Examples

Example 1 -- Get properties for a publishing

Get-JuribaAppRGenericIntegrationProperty -IntegrationId 4 -PublishingId 3201
Sample output 
applicationId         : 1941
applicationName       : Acme Viewer Pro
packageType           : 0
installationProgram   : msiexec /i AcmeViewer.msi /qn
uninstallationProgram : msiexec /x {A1B2C3D4-E5F6-7890-ABCD-EF1234567890} /qn
properties            : {@{id=3; name=Language; value=English},
                         @{id=5; name=TargetOU; value=OU=Desktops,DC=contoso,DC=com}}

Example 2 -- Extract install command for scripting

$props = Get-JuribaAppRGenericIntegrationProperty -IntegrationId 4 -PublishingId 3201
$installCmd = $props.installationProgram
Write-Host "Install command: $installCmd"
Sample output 
Install command: msiexec /i AcmeViewer.msi /qn
Note: This cmdlet calls GET api/v1/integration/generic/{integrationId}/published-app/{publishingId}. The packageType in the response is an integer value (0 = Msi, 4 = IntuneWin, 5 = AppAttach, 6 = Psadt).

Get-JuribaAppRGenericIntegrationPrerequisite

Synopsis

Gets prerequisites for a specific publishing in a generic integration.

Description

Retrieves the collection of prerequisite records associated with a specific publishing. Prerequisites represent other applications or packages that must be installed before the current package. If the publishing was triggered with a prerequisites array, those entries are returned here.

Syntax

Get-JuribaAppRGenericIntegrationPrerequisite
    -IntegrationId <Int32>
    -PublishingId <Int32>

Parameters

ParameterTypeStatusDescription
-Instance String Optional The URL of the App Readiness instance. Not required if connected via Connect-JuribaAppR.
-APIKey String Optional The API key for authentication. Not required if connected via Connect-JuribaAppR.
-IntegrationId Int32 Required The unique identifier of the generic integration.
-PublishingId Int32 Required The unique identifier of the publishing record.

When to Use

Call this cmdlet when your deployment script needs to verify or install dependencies before deploying the main package. If the application has prerequisites defined (for example, a .NET runtime or a Visual C++ redistributable), this cmdlet returns them so your script can ensure they are in place before proceeding.

Examples

Example 1 -- Get prerequisites for a publishing

Get-JuribaAppRGenericIntegrationPrerequisite -IntegrationId 4 -PublishingId 3203
Sample output 
applicationId : 1900
packageType   : 4
name          : .NET 8 Runtime

Example 2 -- Check for prerequisites before deploying

$prereqs = Get-JuribaAppRGenericIntegrationPrerequisite -IntegrationId 4 -PublishingId 3203
if ($prereqs) {
    Write-Host "Prerequisites found: $($prereqs.Count)"
    foreach ($p in $prereqs) {
        Write-Host "  - $($p.name) (App $($p.applicationId), type $($p.packageType))"
    }
} else {
    Write-Host "No prerequisites required."
}
Sample output 
Prerequisites found: 1
  - .NET 8 Runtime (App 1900, type 4)
Note: This cmdlet calls GET api/v1/integration/generic/{integrationId}/published-app/{publishingId}/prerequisites. If the publishing was created without prerequisites, the API returns an empty array.

Get-JuribaAppRGenericIntegrationSource

Synopsis

Downloads the package source file for a publishing in a generic integration.

Description

Downloads the published package file to a local directory. The cmdlet first saves the file with a temporary GUID-based name, then reads the Content-Disposition header from the API response to determine the real file name, and renames the file accordingly. The final file name is returned as a string so your script knows exactly what was downloaded.

Syntax

Get-JuribaAppRGenericIntegrationSource
    -IntegrationId <Int32>
    -PublishingId <Int32>
    -SourcePath <String>

Parameters

ParameterTypeStatusDescription
-Instance String Optional The URL of the App Readiness instance. Not required if connected via Connect-JuribaAppR.
-APIKey String Optional The API key for authentication. Not required if connected via Connect-JuribaAppR.
-IntegrationId Int32 Required The unique identifier of the generic integration.
-PublishingId Int32 Required The unique identifier of the publishing record.
-SourcePath String Required The local directory path where the downloaded file will be saved. The directory must exist.

Download Mechanism

The cmdlet uses a temporary-file-rename approach to ensure safe downloads:

  1. A new GUID is generated as a temporary file name.
  2. The file is downloaded to SourcePath\{guid} using Invoke-WebRequest -OutFile.
  3. The Content-Disposition header is parsed to extract the original file name from the server.
  4. The temporary file is renamed to the original file name.
  5. The original file name is returned as a string.

If the download fails, the temporary file is cleaned up automatically.

When to Use

Call this cmdlet after retrieving the publishing properties and prerequisites. The downloaded file is the actual package (MSI, IntuneWin, PSADT zip, or App Attach VHD) that your script will deploy to the target system.

Examples

Example 1 -- Download a package source

$fileName = Get-JuribaAppRGenericIntegrationSource `
    -IntegrationId 4 `
    -PublishingId 3201 `
    -SourcePath "C:\Packages\Staging"
Write-Host "Downloaded: $fileName"
Sample output 
Downloaded: AcmeViewer_2.1.0.msi

Example 2 -- Download and then install

$props = Get-JuribaAppRGenericIntegrationProperty -IntegrationId 4 -PublishingId 3201
$fileName = Get-JuribaAppRGenericIntegrationSource `
    -IntegrationId 4 `
    -PublishingId 3201 `
    -SourcePath "C:\Packages\Staging"

$fullPath = Join-Path "C:\Packages\Staging" $fileName
Write-Host "Installing $($props.applicationName) from $fullPath..."
Start-Process -FilePath "msiexec" -ArgumentList "/i `"$fullPath`" /qn" -Wait
Sample output 
Installing Acme Viewer Pro from C:\Packages\Staging\AcmeViewer_2.1.0.msi...
Important: The -SourcePath directory must exist before calling this cmdlet. The cmdlet does not create directories. If the directory does not exist, the download will fail.
Note: This cmdlet calls GET api/v1/integration/generic/{integrationId}/published-app/{publishingId}/source. Authentication is passed via the x-api-key header. The response includes a Content-Disposition header with the original file name.

Add-JuribaAppRGenericIntegrationLog

Synopsis

Adds a log entry for a publishing in a generic integration.

Description

Records a log entry against a specific publishing. Use this cmdlet throughout your deployment script to report progress, warnings, and errors back to App Readiness. Log entries are visible in the App Readiness UI and provide an audit trail of what happened during the external publishing process.

Syntax

Add-JuribaAppRGenericIntegrationLog
    -IntegrationId <Int32>
    -PublishingId <Int32>
    -Message <String>
    -Level <String>
    -Date <DateTime>
    [-PublishedAppId <String>]
    [-PublishedAppName <String>]

Parameters

ParameterTypeStatusDescription
-Instance String Optional The URL of the App Readiness instance. Not required if connected via Connect-JuribaAppR.
-APIKey String Optional The API key for authentication. Not required if connected via Connect-JuribaAppR.
-IntegrationId Int32 Required The unique identifier of the generic integration.
-PublishingId Int32 Required The unique identifier of the publishing record.
-Message String Required The log message text.
-Level String Required The severity level. Valid values: Information, Warning, Error, Debug.
-Date DateTime Required The date and time of the log entry. Typically set to (Get-Date).
-PublishedAppId String Optional The identifier of the published application in the target system. Useful for cross-referencing with the external deployment platform.
-PublishedAppName String Optional The name of the published application in the target system.

When to Use

Use this cmdlet at each significant step of your deployment script to create a complete audit trail in App Readiness. Common log points include: package download started, package download completed, installation started, installation succeeded or failed, and validation completed. Logging errors before calling Update-JuribaAppRGenericIntegrationPublishingState -PublishingState Failed ensures the failure reason is captured.

Examples

Example 1 -- Log an informational message

Add-JuribaAppRGenericIntegrationLog `
    -IntegrationId 4 `
    -PublishingId 3201 `
    -Message "Package uploaded successfully" `
    -Level "Information" `
    -Date (Get-Date)
Sample output 
(no output -- HTTP 200 returned on success)

Example 2 -- Log an error with published app details

Add-JuribaAppRGenericIntegrationLog `
    -IntegrationId 4 `
    -PublishingId 3201 `
    -Message "Installation failed: exit code 1603 (fatal error during installation)" `
    -Level "Error" `
    -Date (Get-Date) `
    -PublishedAppId "ITSM-4821" `
    -PublishedAppName "Acme Viewer Pro"
Sample output 
(no output -- HTTP 200 returned on success)

Example 3 -- Log multiple stages in a deployment script

$intId = 4
$pubId = 3201

# Log: starting download
Add-JuribaAppRGenericIntegrationLog -IntegrationId $intId -PublishingId $pubId `
    -Message "Starting package download" -Level "Information" -Date (Get-Date)

$fileName = Get-JuribaAppRGenericIntegrationSource -IntegrationId $intId `
    -PublishingId $pubId -SourcePath "C:\Packages\Staging"

# Log: download complete
Add-JuribaAppRGenericIntegrationLog -IntegrationId $intId -PublishingId $pubId `
    -Message "Downloaded $fileName" -Level "Information" -Date (Get-Date)

# Log: starting install
Add-JuribaAppRGenericIntegrationLog -IntegrationId $intId -PublishingId $pubId `
    -Message "Starting silent installation" -Level "Information" -Date (Get-Date)

# ... perform installation ...

# Log: success
Add-JuribaAppRGenericIntegrationLog -IntegrationId $intId -PublishingId $pubId `
    -Message "Installation completed successfully" -Level "Information" -Date (Get-Date)
Sample output 
(no output -- each call returns HTTP 200 on success)
Note: This cmdlet posts to POST api/v1/integration/generic/{integrationId}/published-app/{publishingId}/logs. The -Level parameter accepts exactly four values: Information, Warning, Error, and Debug. Invalid values will cause a PowerShell validation error before the API call is made.

Update-JuribaAppRGenericIntegrationPublishingState

Synopsis

Updates the state of a publishing in a generic integration.

Description

Marks a publishing record as either Succeeded or Failed. This is the final call in a generic integration publishing script and tells App Readiness whether the external deployment completed successfully. Optionally, you can supply the published application ID and version in the target system for tracking purposes. This cmdlet supports ShouldProcess, so you can use -WhatIf or -Confirm to preview the state change.

Syntax

Update-JuribaAppRGenericIntegrationPublishingState
    -IntegrationId <Int32>
    -PublishingId <Int32>
    -PublishingState <String>
    [-PublishedAppId <String>]
    [-PublishedApplicationVersion <String>]
    [-WhatIf] [-Confirm]

Parameters

ParameterTypeStatusDescription
-Instance String Optional The URL of the App Readiness instance. Not required if connected via Connect-JuribaAppR.
-APIKey String Optional The API key for authentication. Not required if connected via Connect-JuribaAppR.
-IntegrationId Int32 Required The unique identifier of the generic integration.
-PublishingId Int32 Required The unique identifier of the publishing record.
-PublishingState String Required The new state. Valid values: Succeeded, Failed.
-PublishedAppId String Optional The identifier assigned to the application in the target deployment system. Stored in App Readiness for cross-reference.
-PublishedApplicationVersion String Optional The version string of the published application in the target system.

When to Use

Call this cmdlet as the very last step in your generic integration script. After all deployment work is complete and logs have been written, update the state to Succeeded. If any step failed, update the state to Failed so that App Readiness can flag the publishing for review or retry. Always log errors with Add-JuribaAppRGenericIntegrationLog before marking the state as failed, so the failure reason is recorded.

Examples

Example 1 -- Mark a publishing as succeeded

Update-JuribaAppRGenericIntegrationPublishingState `
    -IntegrationId 4 `
    -PublishingId 3201 `
    -PublishingState "Succeeded" `
    -PublishedAppId "ITSM-4821" `
    -PublishedApplicationVersion "2.1.0"
Sample output 
(no output -- HTTP 200 returned on success)

Example 2 -- Mark a publishing as failed

# Log the error first
Add-JuribaAppRGenericIntegrationLog -IntegrationId 4 -PublishingId 3201 `
    -Message "MSI installation returned exit code 1603" -Level "Error" -Date (Get-Date)

# Then mark as failed
Update-JuribaAppRGenericIntegrationPublishingState `
    -IntegrationId 4 `
    -PublishingId 3201 `
    -PublishingState "Failed"
Sample output 
(no output -- HTTP 200 returned on success)

Example 3 -- Preview with -WhatIf

Update-JuribaAppRGenericIntegrationPublishingState `
    -IntegrationId 4 `
    -PublishingId 3201 `
    -PublishingState "Succeeded" `
    -WhatIf
Sample output 
What if: Performing the operation "Update state to 'Succeeded'" on target
"Integration 4, Publishing 3201".

Example 4 -- Complete end-to-end generic integration script

$intId = 4
$stagingDir = "C:\Packages\Staging"

# Step 1: Get pending publishings
$publishingIds = Get-JuribaAppRGenericIntegrationPublishing -IntegrationId $intId
Write-Host "Found $($publishingIds.Count) pending publishing(s)."

foreach ($pubId in $publishingIds) {
    try {
        # Step 2: Get properties
        $props = Get-JuribaAppRGenericIntegrationProperty -IntegrationId $intId -PublishingId $pubId
        Write-Host "Processing: $($props.applicationName) (Publishing $pubId)"

        # Step 3: Check prerequisites
        $prereqs = Get-JuribaAppRGenericIntegrationPrerequisite -IntegrationId $intId -PublishingId $pubId
        if ($prereqs) {
            Add-JuribaAppRGenericIntegrationLog -IntegrationId $intId -PublishingId $pubId `
                -Message "Verifying $($prereqs.Count) prerequisite(s)" -Level "Information" -Date (Get-Date)
        }

        # Step 4: Download package
        Add-JuribaAppRGenericIntegrationLog -IntegrationId $intId -PublishingId $pubId `
            -Message "Downloading package source" -Level "Information" -Date (Get-Date)
        $fileName = Get-JuribaAppRGenericIntegrationSource -IntegrationId $intId `
            -PublishingId $pubId -SourcePath $stagingDir

        # Step 5: Deploy (example: copy to distribution share)
        $destShare = "\\deploy-srv\Packages$\$($props.applicationName)"
        if (-not (Test-Path $destShare)) { New-Item $destShare -ItemType Directory | Out-Null }
        Copy-Item (Join-Path $stagingDir $fileName) $destShare -Force
        Add-JuribaAppRGenericIntegrationLog -IntegrationId $intId -PublishingId $pubId `
            -Message "Copied $fileName to $destShare" -Level "Information" -Date (Get-Date)

        # Step 6: Mark succeeded
        Update-JuribaAppRGenericIntegrationPublishingState -IntegrationId $intId `
            -PublishingId $pubId -PublishingState "Succeeded" `
            -PublishedAppId $props.applicationName -PublishedApplicationVersion "1.0"
        Write-Host "  Succeeded."
    }
    catch {
        Add-JuribaAppRGenericIntegrationLog -IntegrationId $intId -PublishingId $pubId `
            -Message "FAILED: $($_.Exception.Message)" -Level "Error" -Date (Get-Date)
        Update-JuribaAppRGenericIntegrationPublishingState -IntegrationId $intId `
            -PublishingId $pubId -PublishingState "Failed"
        Write-Warning "  Failed: $($_.Exception.Message)"
    }
}
Sample output 
Found 2 pending publishing(s).
Processing: Acme Viewer Pro (Publishing 3201)
  Succeeded.
Processing: Contoso Editor (Publishing 3207)
  Succeeded.
Note: This cmdlet sends a PUT request to api/v1/integration/generic/{integrationId}/published-app/{publishingId}. The -PublishingState parameter accepts exactly two values: Succeeded and Failed. The ShouldProcess support means that -WhatIf and -Confirm work as expected, and the cmdlet respects the $ConfirmPreference variable.
