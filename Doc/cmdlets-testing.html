Testing Cmdlets

These cmdlets manage the automated smoke-testing lifecycle in Juriba App Readiness. They interact with the ACE (Automated Compatibility Engine) framework, which provisions virtual machines, installs packaged applications, runs compatibility checks, and records pass/fail/warning results.

Get-JuribaAppRTestApplication

Synopsis

Gets applications available for testing in the ACE testing environment.

Syntax

# Mode 1 -- All test applications (default)
Get-JuribaAppRTestApplication

# Mode 2 -- Specific application
Get-JuribaAppRTestApplication -AppId <Int32>

# Mode 3 -- All environments
Get-JuribaAppRTestApplication -AllEnvironments

Parameters

ParameterTypeStatusDescription
-Instance String Optional The URL of the App Readiness instance. Not required if connected via Connect-JuribaAppR.
-APIKey String Optional The API key for authentication. Not required if connected via Connect-JuribaAppR.
-AppId Int32 Optional The unique identifier of an application. When provided, returns test details for that application only.
-AllEnvironments Switch Optional When specified, returns applications across all testing environments rather than just the default environment.

When to Use

Use this cmdlet to discover which applications are available for smoke testing, check their current test status, or enumerate applications across multiple ACE environments. The ACE framework automatically provisions clean virtual machines, installs the packaged application, executes compatibility checks, and records results. This cmdlet reads the current state of that process.

Examples

Example 1 -- List all applications available for testing

Get-JuribaAppRTestApplication | Format-Table AppId, Name, TestStatus -AutoSize
Sample output 
AppId Name                        TestStatus
----- ----                        ----------
  101 7-Zip                       Passed
  204 Google Chrome Enterprise    Testing
  312 Notepad++                   Failed
  415 VLC Media Player            NotTested
  518 PuTTY                       Passed

Example 2 -- Get test details for a single application

Get-JuribaAppRTestApplication -AppId 312
Sample output 
AppId           : 312
Name            : Notepad++
Version         : 8.6.9
TestStatus      : Failed
PackagesTested  : {Msi, Msix}
LastTestDate    : 2026-03-28T15:42:18Z
VMGroupId       : 2
FailureReason   : Install returned exit code 1603

Example 3 -- List applications across all environments

Get-JuribaAppRTestApplication -AllEnvironments | Group-Object Environment | Format-Table Name, Count
Sample output 
Name             Count
----             -----
Windows 11 24H2    38
Windows 10 22H2    25
Windows 11 23H2    12
Note: The -AppId and -AllEnvironments parameters are mutually exclusive. If both are provided, -AppId takes precedence.

Start-JuribaAppRSmokeTest

Synopsis

Initiates a smoke test for a specific application and package type.

Syntax

# Mode 1 -- Auto-assigned VM (single test)
Start-JuribaAppRSmokeTest -AppId <Int32> -PackageType <String>

# Mode 2 -- Specific VM group (manual test)
Start-JuribaAppRSmokeTest -AppId <Int32> -PackageType <String> -VMGroupId <Int32>

Parameters

ParameterTypeStatusDescription
-Instance String Optional The URL of the App Readiness instance. Not required if connected via Connect-JuribaAppR.
-APIKey String Optional The API key for authentication. Not required if connected via Connect-JuribaAppR.
-AppId Int32 Required The unique identifier of the application to test.
-PackageType String Required The package type to test (e.g. Msi, Msix, IntuneWin, AppV).
-VMGroupId Int32 Optional The VM group (pool) to run the test on. If omitted, ACE automatically assigns a VM from the default pool.

When to Use

Use this cmdlet to kick off an automated smoke test after packaging is complete. In Mode 1 (without -VMGroupId), ACE provisions a VM from the default pool, installs the package, and runs the test suite automatically. In Mode 2 (with -VMGroupId), the test runs on a specific VM group, which is useful when you have multiple OS environments or need to target a particular configuration.

This cmdlet supports -WhatIf and -Confirm via SupportsShouldProcess.

Examples

Example 1 -- Start an MSI smoke test with automatic VM assignment

Start-JuribaAppRSmokeTest -AppId 101 -PackageType Msi
Sample output 
TestId      : 847
AppId       : 101
PackageType : Msi
VMGroupId   : 1
Status      : Queued
StartedAt   : 2026-03-30T10:15:22Z

Example 2 -- Start an IntuneWin test on a specific VM group

Start-JuribaAppRSmokeTest -AppId 204 -PackageType IntuneWin -VMGroupId 3
Sample output 
TestId      : 848
AppId       : 204
PackageType : IntuneWin
VMGroupId   : 3
Status      : Queued
StartedAt   : 2026-03-30T10:16:05Z

Example 3 -- Preview with -WhatIf

Start-JuribaAppRSmokeTest -AppId 312 -PackageType Msix -WhatIf
Sample output 
What if: Performing the operation "Start smoke test" on target "App 312 (Msix)".
Note: Mode 1 uses an HTTP POST to the singleTest endpoint. Mode 2 uses an HTTP PUT to the manualTest endpoint. The API methods differ because manual tests reserve a specific VM rather than requesting one from the pool.

Stop-JuribaAppRSmokeTest

Synopsis

Cancels a running smoke test.

Syntax

Stop-JuribaAppRSmokeTest

Parameters

ParameterTypeStatusDescription
-Instance String Optional The URL of the App Readiness instance. Not required if connected via Connect-JuribaAppR.
-APIKey String Optional The API key for authentication. Not required if connected via Connect-JuribaAppR.

When to Use

Use this cmdlet to cancel a smoke test that is currently in progress. This is useful when a test has been started by mistake, is taking too long, or the application configuration has changed and a re-test is needed. The associated virtual machine is released back to the pool after cancellation.

Examples

Example 1 -- Cancel the current smoke test

Stop-JuribaAppRSmokeTest
Sample output 
Status    : Cancelled
Message   : Smoke test cancelled successfully.
CancelledAt : 2026-03-30T10:20:44Z

Example 2 -- Cancel with confirmation prompt

Stop-JuribaAppRSmokeTest -Confirm
Sample output 
Confirm
Are you sure you want to perform this action?
Performing the operation "Cancel" on target "Smoke test".
[Y] Yes  [A] Yes to All  [N] No  [L] No to All  [S] Suspend  [?] Help (default is "Y"): Y

Status    : Cancelled
Message   : Smoke test cancelled successfully.
CancelledAt : 2026-03-30T10:21:12Z
Important: This cmdlet cancels the smoke test globally -- it does not target a specific application or test ID. If multiple tests are queued, the currently running test is cancelled and the VM is released. There is no parameter to cancel a specific test by ID.

Get-JuribaAppRTestResult

Synopsis

Gets smoke test results for an application, including pass/fail status, warnings, and failure details.

Syntax

# Mode 1 -- All results for an application
Get-JuribaAppRTestResult -AppId <Int32>

# Mode 2 -- Filtered by VM group and package type
Get-JuribaAppRTestResult -AppId <Int32> -VMGroupId <Int32> -PackageType <String>

Parameters

ParameterTypeStatusDescription
-Instance String Optional The URL of the App Readiness instance. Not required if connected via Connect-JuribaAppR.
-APIKey String Optional The API key for authentication. Not required if connected via Connect-JuribaAppR.
-AppId Int32 Required The unique identifier of the application.
-VMGroupId Int32 Optional Filter results to a specific VM group. Must be used together with -PackageType.
-PackageType String Optional Filter results to a specific package type. Must be used together with -VMGroupId.

When to Use

Use this cmdlet after a smoke test completes to retrieve the results. Mode 1 returns all test results across every package type and VM group for the application. Mode 2 narrows the results to a specific combination of VM group and package type, which is useful when an application has been tested against multiple configurations.

Examples

Example 1 -- Get all test results for an application

Get-JuribaAppRTestResult -AppId 101
Sample output 
PackageType : Msi
VMGroupId   : 1
Result      : Passed
Warnings    : 0
Failures    : 0
TestDate    : 2026-03-29T08:14:33Z

PackageType : Msix
VMGroupId   : 1
Result      : PassedWithWarnings
Warnings    : 2
Failures    : 0
TestDate    : 2026-03-29T09:02:17Z

PackageType : IntuneWin
VMGroupId   : 2
Result      : Failed
Warnings    : 1
Failures    : 3
TestDate    : 2026-03-29T10:45:08Z
FailureDetails : {Install timeout after 300s, Service 7zService failed to start, Uninstall left orphaned registry keys}

Example 2 -- Get filtered results for a specific VM group and package type

Get-JuribaAppRTestResult -AppId 204 -VMGroupId 1 -PackageType Msi
Sample output 
PackageType    : Msi
VMGroupId      : 1
Result         : Passed
Warnings       : 0
Failures       : 0
InstallResult  : Success
LaunchResult   : Success
UninstallResult: Success
TestDate       : 2026-03-28T14:22:51Z
Duration       : 00:04:37

Example 3 -- Pipe results into a report

Get-JuribaAppRTestResult -AppId 101 | Select-Object PackageType, Result, Warnings, Failures | Format-Table -AutoSize
Sample output 
PackageType Result              Warnings Failures
----------- ------              -------- --------
Msi         Passed                     0        0
Msix        PassedWithWarnings         2        0
IntuneWin   Failed                     1        3
Note: In Mode 2, both -VMGroupId and -PackageType must be provided together. If only one is supplied, the cmdlet falls back to Mode 1 and returns all results for the application.

Get-JuribaAppRTestStats

Synopsis

Gets aggregate testing statistics from Juriba App Readiness.

Syntax

# Overall statistics
Get-JuribaAppRTestStats

# Per-application statistics
Get-JuribaAppRTestStats -AppId <Int32>

Parameters

ParameterTypeStatusDescription
-Instance String Optional The URL of the App Readiness instance. Not required if connected via Connect-JuribaAppR.
-APIKey String Optional The API key for authentication. Not required if connected via Connect-JuribaAppR.
-AppId Int32 Optional The unique identifier of an application. If omitted, returns overall statistics across all applications.

When to Use

Use this cmdlet to build dashboards, generate summary reports, or quickly check the health of your testing pipeline. Without -AppId, it returns organisation-wide totals. With -AppId, it returns the breakdown for a single application.

Examples

Example 1 -- Get overall testing statistics

Get-JuribaAppRTestStats
Sample output 
TotalTests      : 284
Green           : 201
Red             : 47
Amber           : 36
NotTested       : 112
PassRate        : 70.8%
LastUpdated     : 2026-03-31T23:59:59Z

Example 2 -- Get statistics for a single application

Get-JuribaAppRTestStats -AppId 101
Sample output 
AppId           : 101
Name            : 7-Zip
TotalTests      : 6
Green           : 4
Red             : 1
Amber           : 1
PassRate        : 66.7%

Example 3 -- Dashboard-style one-liner

$s = Get-JuribaAppRTestStats; "Tests: $($s.TotalTests) | Passed: $($s.Green) | Failed: $($s.Red) | Warnings: $($s.Amber) | Pass rate: $($s.PassRate)"
Sample output 
Tests: 284 | Passed: 201 | Failed: 47 | Warnings: 36 | Pass rate: 70.8%
Note: The colour-coded counts (Green, Red, Amber) correspond to the traffic-light indicators in the App Readiness web interface. Green means all checks passed, Red means at least one check failed, and Amber means warnings were raised but no hard failures occurred.
