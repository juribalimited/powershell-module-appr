Quality Review Cmdlets

Quality Review (QR) is the final gate before an application is published. During QR, a reviewer inspects the packaged application against a checklist of criteria -- correct install/uninstall behaviour, shortcut placement, file associations, registry hygiene, and more. These cmdlets retrieve the QR status, checklist results, and optional screenshot evidence for an application.

Get-JuribaAppRQualityReview

Synopsis

Gets quality review results for an application, including checklist status and optional screenshot data.

Syntax

# QR status only
Get-JuribaAppRQualityReview -AppId <Int32>

# QR status filtered by package type
Get-JuribaAppRQualityReview -AppId <Int32> -PackageType <String>

# QR status with screenshots
Get-JuribaAppRQualityReview -AppId <Int32> -PackageType <String> -IncludeScreenshots

Parameters

ParameterTypeStatusDescription
-Instance String Optional The URL of the App Readiness instance. Not required if connected via Connect-JuribaAppR.
-APIKey String Optional The API key for authentication. Not required if connected via Connect-JuribaAppR.
-AppId Int32 Required The unique identifier of the application.
-PackageType String Optional The package type to get QR results for (e.g. Msi, Msix, IntuneWin, AppV). Required when using -IncludeScreenshots.
-IncludeScreenshots Switch Optional When specified, retrieves screenshot data captured during the QR process. Requires -PackageType to be set.

The QR Checklist

The quality review checklist is a configurable set of verification items that reviewers work through after an application has been packaged and tested. Typical checklist items include:

  • Install verification -- the package installs silently without errors.
  • Uninstall verification -- the package removes cleanly with no orphaned files or registry entries.
  • Shortcut validation -- Start Menu and Desktop shortcuts are created in the correct locations.
  • File association check -- registered file types open with the correct application.
  • Service and driver check -- any services or drivers installed are running as expected.
  • Screenshot evidence -- visual proof that the application launches and displays correctly.

Each checklist item is marked as Passed, Failed, or Not Reviewed. The overall QR status is derived from the individual item results.

When to Use

Use this cmdlet to check whether an application has passed quality review, to retrieve the detailed checklist results for audit or reporting purposes, or to pull screenshot evidence into an automated compliance report. In a typical pipeline, you would call this after smoke testing completes and the application enters the QR stage.

Examples

Example 1 -- Get QR status for an application

Get-JuribaAppRQualityReview -AppId 101
Sample output 
AppId          : 101
Name           : 7-Zip
QRStatus       : Passed
ReviewedBy     : jsmith
ReviewedDate   : 2026-03-30T11:45:00Z
ChecklistItems : {Install: Passed, Uninstall: Passed, Shortcuts: Passed,
                  FileAssociations: Passed, Services: NotApplicable}

Example 2 -- Get QR results for a specific package type

Get-JuribaAppRQualityReview -AppId 204 -PackageType Msi
Sample output 
AppId          : 204
Name           : Google Chrome Enterprise
PackageType    : Msi
QRStatus       : Failed
ReviewedBy     : amorgan
ReviewedDate   : 2026-03-29T16:30:22Z
ChecklistItems : {Install: Passed, Uninstall: Failed, Shortcuts: Passed,
                  FileAssociations: Passed, Services: Passed}
FailureNotes   : Uninstall leaves Chrome updater service registered in HKLM.

Example 3 -- Get QR results with screenshots

Get-JuribaAppRQualityReview -AppId 312 -PackageType Msi -IncludeScreenshots
Sample output 
AppId          : 312
Name           : Notepad++
PackageType    : Msi
QRStatus       : Passed
ReviewedBy     : bkelly
ReviewedDate   : 2026-03-31T09:12:48Z
ChecklistItems : {Install: Passed, Uninstall: Passed, Shortcuts: Passed,
                  FileAssociations: Passed, Services: NotApplicable}
Screenshots    : {@{Name=post-install-desktop.png; Size=284672;
                    ContentType=image/png; Data=iVBORw0KGgoAAAANSUhEUg...},
                  @{Name=app-launch-main-window.png; Size=198400;
                    ContentType=image/png; Data=iVBORw0KGgoAAAANSUhEUg...},
                  @{Name=post-uninstall-clean.png; Size=156928;
                    ContentType=image/png; Data=iVBORw0KGgoAAAANSUhEUg...}}

Example 4 -- Save screenshots to disk

$qr = Get-JuribaAppRQualityReview -AppId 312 -PackageType Msi -IncludeScreenshots
foreach ($shot in $qr.Screenshots) {
    $bytes = [Convert]::FromBase64String($shot.Data)
    [IO.File]::WriteAllBytes("C:\QR-Evidence\$($shot.Name)", $bytes)
    Write-Host "Saved $($shot.Name) ($($shot.Size) bytes)"
}
Sample output 
Saved post-install-desktop.png (284672 bytes)
Saved app-launch-main-window.png (198400 bytes)
Saved post-uninstall-clean.png (156928 bytes)
Note on screenshot data: When -IncludeScreenshots is used, the Screenshots property contains an array of objects. Each object has a Name, Size (in bytes), ContentType (MIME type), and Data field. The Data field holds the image as a Base64-encoded string. To write the image to disk, decode it with [Convert]::FromBase64String() as shown in Example 4.
Important: The -IncludeScreenshots switch requires -PackageType to be specified. If -IncludeScreenshots is used without -PackageType, the screenshots are not retrieved and only the base QR status is returned.
