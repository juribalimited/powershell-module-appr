Instance Configuration Cmdlets

These cmdlets retrieve information about the App Readiness instance itself: version details, default settings, user accounts, and virtual machine groups. Use them to verify your environment before running automation workflows.

Get-JuribaAppRAboutInfo

Retrieves general settings and version information about the connected App Readiness instance. Returns build number, product version, and server configuration details.

Syntax

Get-JuribaAppRAboutInfo
    [-Instance <String>]
    [-APIKey <String>]

Parameters

Name Type Required Default Description
-Instance String Optional Current connection The URL of the App Readiness instance. Not required if connected via Connect-JuribaAppR.
-APIKey String Optional Current connection The API key for authentication. Not required if connected via Connect-JuribaAppR.

When to Use

Call this cmdlet at the start of a script to confirm the instance is reachable and to check its version. This is especially useful when your script relies on features introduced in a specific release (for example, MSIX App Attach support added in v6).

Examples

Example 1: Check instance version before running v6-specific code

$info = Get-JuribaAppRAboutInfo
if ($info.version -ge "6.0") {
    Write-Host "Running v6 workflow with MSIX App Attach support"
    # ... v6-specific automation here ...
} else {
    Write-Host "Instance is running $($info.version) - skipping App Attach steps"
}
Sample output 
version       : 6.0.1.342
productName   : App Readiness
serverName    : APPR-PROD-01
databaseName  : AppReadiness
copyright     : Juriba Ltd

Example 2: Retrieve version using explicit credentials

Get-JuribaAppRAboutInfo -Instance "https://appr.contoso.com" -APIKey "a1b2c3d4-e5f6-7890-abcd-ef1234567890"
Sample output 
version       : 5.2.4.218
productName   : App Readiness
serverName    : APPR-UAT-03
databaseName  : AppReadiness_UAT
copyright     : Juriba Ltd

Notes

  • This cmdlet calls the api/app/about/info endpoint using a GET request.
  • No special permissions are required beyond a valid API key.
  • The version string follows major.minor.patch.build format.

Get-JuribaAppRDefaultSettings

Retrieves default settings for the App Readiness instance, including VM group assignments for repackaging, testing, and UAT, the enabled output package formats, and other configuration flags. Returns a parsed object with a convenience bitmask for output formats.

Syntax

Get-JuribaAppRDefaultSettings
    [-Instance <String>]
    [-APIKey <String>]

Parameters

Name Type Required Default Description
-Instance String Optional Current connection The URL of the App Readiness instance. Not required if connected via Connect-JuribaAppR.
-APIKey String Optional Current connection The API key for authentication. Not required if connected via Connect-JuribaAppR.

Output Format Bitmask

The OutputFormatBitmask property is a bitwise combination of the enabled output formats. Use this value when creating applications to specify which package types to produce.

Format Bit Value Description
MSI1Windows Installer package
App-V2Microsoft App-V virtual package
MSIX4MSIX modern package
MSIX App Attach8Azure Virtual Desktop App Attach (VHD/VHDX)
IntuneWin32Microsoft Intune Win32 wrapper
PSADT128PowerShell App Deployment Toolkit wrapper

For example, a bitmask of 37 means MSI (1) + MSIX (4) + IntuneWin (32) are enabled.

When to Use

Call this cmdlet to discover which output formats are enabled and which VM groups are configured before submitting packaging jobs. If no output formats are enabled, the cmdlet emits a warning because packaging jobs will fail without at least one format selected.

Examples

Example 1: View all default settings

$settings = Get-JuribaAppRDefaultSettings
$settings
Sample output 
VMGroupForRepackaging : 1
VMGroupForTesting    : 2
VMGroupForUAT        : 3
OutputFormats        : {[MSI, True], [AppV, False], [MSIX, True], [MSIXAppAttach, False], [IntuneWin, True], [PSADT, False]}
OutputFormatBitmask  : 37
Raw                  : {@{defaultSettingId=1; defaultSettingType=1; value=true}, @{defaultSettingId=2; defaultSettingType=2; value=false}, ...}

Example 2: Check which output formats are enabled

$settings = Get-JuribaAppRDefaultSettings
$settings.OutputFormats.GetEnumerator() | Where-Object { $_.Value -eq $true } | ForEach-Object {
    Write-Host "Enabled: $($_.Key)"
}
Sample output 
Enabled: MSI
Enabled: MSIX
Enabled: IntuneWin

Example 3: Use bitmask when creating an application

# Use the instance default output formats
$settings = Get-JuribaAppRDefaultSettings
$outputFormat = $settings.OutputFormatBitmask  # e.g. 37

# Pass to New-JuribaAppRApplication later
Write-Host "Will produce output formats with bitmask: $outputFormat"

Notes

  • The raw API response is preserved in the Raw property for diagnostic purposes.
  • Setting types 11, 12, and 13 map to the repackaging, testing, and UAT VM group IDs respectively.
  • If OutputFormatBitmask is 0, a warning is emitted. Check the Default Settings page in the App Readiness UI to enable at least one format.
  • Use -Verbose to see the raw setting-type-to-value mapping during parsing.

Get-JuribaAppRUser

Retrieves user information from App Readiness. Supports three modes: current authenticated user (default), a specific user by ID, or all users in the system.

Syntax

# Current user (default)
Get-JuribaAppRUser [-Me]
    [-Instance <String>] [-APIKey <String>]

# Specific user by ID
Get-JuribaAppRUser -UserId <Int32>
    [-Instance <String>] [-APIKey <String>]

# All users
Get-JuribaAppRUser -All
    [-Instance <String>] [-APIKey <String>]

Parameters

Name Type Required Default Description
-Instance String Optional Current connection The URL of the App Readiness instance.
-APIKey String Optional Current connection The API key for authentication.
-UserId Int32 Required (ById set) None The unique identifier of a specific user to retrieve.
-All Switch Optional False When specified, returns all users in the system.
-Me Switch Optional True (default set) When specified, returns details for the currently authenticated user. This is the default behavior.

When to Use

Use -Me (or no parameters) to confirm which account your API key maps to. Use -All to look up a user ID before assigning application ownership with Set-JuribaAppRApplicationOwner. Use -UserId to retrieve details for a known user.

Examples

Example 1: Get the current user

Get-JuribaAppRUser
Sample output 
userId      : 5
userName    : bob.kelly
displayName : Bob Kelly
email       : bob.kelly@contoso.com
role        : Administrator
isActive    : True

Example 2: Get a specific user by ID

Get-JuribaAppRUser -UserId 12
Sample output 
userId      : 12
userName    : sarah.chen
displayName : Sarah Chen
email       : sarah.chen@contoso.com
role        : Packager
isActive    : True

Example 3: List all users

Get-JuribaAppRUser -All | Format-Table userId, displayName, role, isActive
Sample output 
userId displayName    role           isActive
------ -----------    ----           --------
     1 Admin          Administrator      True
     5 Bob Kelly      Administrator      True
    12 Sarah Chen     Packager           True
    18 James Wright   Reviewer           True
    24 Maria Lopez    ReadOnly          False

Notes

  • The default parameter set is Me, so calling with no parameters is equivalent to -Me.
  • The three parameter sets (Me, ById, All) are mutually exclusive.
  • API endpoints: api/apm/user/whoAmI/full, api/apm/user/{id}, api/apm/users/all.

Get-JuribaAppRVMGroup

Retrieves the list of virtual machine groups (VM pools) configured in App Readiness. Each VM group represents a testing environment used during smoke testing, repackaging, or UAT stages.

Syntax

Get-JuribaAppRVMGroup
    [-VMGroupId <Int32>]
    [-Instance <String>]
    [-APIKey <String>]

Parameters

Name Type Required Default Description
-Instance String Optional Current connection The URL of the App Readiness instance.
-APIKey String Optional Current connection The API key for authentication.
-VMGroupId Int32 Optional None (returns all) The unique identifier of a specific VM group to retrieve. If omitted, returns all VM groups.

VM Pool Status Values

Each VM group includes a status indicator that describes the current state of the pool.

Status Meaning
OnlineThe pool is healthy and VMs are available for testing.
BusyAll VMs in the pool are currently in use. New jobs will queue.
OfflineThe pool is disabled or unreachable. Jobs targeting this pool will fail.
ProvisioningVMs are being created or restored to snapshot. The pool will come online shortly.

When to Use

Call this cmdlet to discover available VM pools and their IDs before starting smoke tests or to verify that a pool is online. The VM group IDs returned here correspond to the IDs shown in Get-JuribaAppRDefaultSettings (VMGroupForRepackaging, VMGroupForTesting, VMGroupForUAT).

Examples

Example 1: List all VM groups

Get-JuribaAppRVMGroup | Format-Table vmGroupId, name, status, vmCount
Sample output 
vmGroupId name                       status  vmCount
--------- ----                       ------  -------
        1 Win10-22H2-Packaging       Online        4
        2 Win11-23H2-SmokeTest       Online        6
        3 Win11-23H2-UAT             Busy          2
        4 Win10-LTSC-Legacy          Offline       2

Example 2: Get details for a specific VM group

Get-JuribaAppRVMGroup -VMGroupId 2
Sample output 
vmGroupId       : 2
name            : Win11-23H2-SmokeTest
description     : Windows 11 23H2 pool for automated smoke testing
status          : Online
vmCount         : 6
availableVMs    : 4
snapshotName    : CleanBaseline-2026-03
hypervisorType  : HyperV

Example 3: Verify pool is online before starting a test

$pool = Get-JuribaAppRVMGroup -VMGroupId 2
if ($pool.status -ne "Online") {
    Write-Warning "VM pool '$($pool.name)' is $($pool.status). Aborting test."
    return
}
Write-Host "Pool ready - $($pool.availableVMs) of $($pool.vmCount) VMs available"

Notes

  • When called without -VMGroupId, the cmdlet calls api/virtual-machine/group/list; with an ID it calls api/virtual-machine/group/{id}.
  • The VM group IDs are stable integers that can be stored in configuration files for repeated use.
  • If a VM group is Offline, check the Hyper-V or Azure host connectivity in the App Readiness administration console.
